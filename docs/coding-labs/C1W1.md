You've seen the idea: fit a straight line through your data, then read predictions off
the line. Now let's build it three ways, from the inside out:

1. **From scratch, the closed-form way** — one matrix equation that jumps straight to the best line.
2. **From scratch, the iterative way** — gradient descent, the same "roll downhill" engine you'll reuse for *every* model later, neural networks included.
3. **The library way** — scikit-learn, in three lines, which is what you'd actually type on the job.

All three land on the *same* line. Seeing why is the whole point.

---

## 0. Setup and some data

We'll generate data that follows a known line — `price = 4 + 3 × size` — plus random
noise, so we can check whether our code recovers the `4` and the `3`.

```python
import numpy as np

rng = np.random.default_rng(42)          # fixed seed → reproducible "random" data
m = 100                                   # number of training examples
X = 2 * rng.random((m, 1))               # feature: house size (m rows, 1 column)
y = 4 + 3 * X + rng.standard_normal((m, 1))   # target: price = 4 + 3·size + noise
```

`X` is a column of sizes; `y` is a column of prices. In the notation from the lesson,
`m = 100`, each row is one training example `(x⁽ⁱ⁾, y⁽ⁱ⁾)`.

---

## 1. The model as code

The lesson's model is `f(x) = w·x + b`. Written for many features at once it's a **weighted
sum plus a bias** — which is just a **dot product**. The standard trick that makes the code
clean is to bolt a column of `1`s onto `X`, so the bias `b` becomes "the weight on a feature
that's always 1." Then prediction for the whole dataset is one matrix multiply:

```python
X_b = np.c_[np.ones((m, 1)), X]          # prepend x0 = 1 to every row (the bias column)

def predict(X_b, theta):
    return X_b @ theta                   # ŷ = X · θ   (θ = [b, w])
```

Here `theta` holds both parameters: `theta[0]` is the bias `b`, `theta[1]` is the weight `w`.
The `@` operator is matrix multiplication.

---

## 2. Measuring how good a line is: the cost

Training means *finding the `theta` that fits best* — so we need a number for "how bad is
this line." That's the **mean squared error** (the same squared-error cost from the lesson,
and the red bars you saw in the interactive):

```python
def mse(X_b, y, theta):
    errors = X_b @ theta - y             # residual for each point: prediction − truth
    return float((errors.T @ errors) / len(y))   # mean of the squared residuals
```

Lower is better. Every method below is just a different way to make this number as small
as possible.

---

## 3. Route A — the closed-form solution (the normal equation)

For linear regression there's a beautiful shortcut: a single equation that computes the
best `theta` directly, no iteration. It's called the **normal equation**:

$$\theta = (X^\top X)^{-1} X^\top y$$

```python
theta_best = np.linalg.inv(X_b.T @ X_b) @ X_b.T @ y
print(theta_best.ravel())        # → about [3.9, 3.0]: it recovered the 4 and the 3
```

That's it — the exact best-fit line in one line of algebra. (The values aren't *exactly*
4 and 3 because the noise makes the original parameters impossible to recover perfectly;
the smaller and noisier the data, the further off they'll be.)

So why ever do anything more complicated? Because inverting `Xᵀ X` gets **slow** as the
number of features grows, and it breaks down entirely for the huge, many-feature problems
(and non-linear models like neural nets) you'll hit later. For those we need a method that
*scales* — gradient descent.

---

## 4. Route B — gradient descent, from scratch

Here's the mental picture Géron uses: **you're lost on a mountain in thick fog, and you
want the valley bottom.** You can't see the whole landscape — but you *can* feel the slope
under your feet. So you take a small step in the steepest downhill direction, and repeat.
That's gradient descent. The "landscape" is the cost function; the "valley bottom" is the
best `theta`.

The slope of the cost with respect to the parameters is its **gradient**. For the MSE it
works out to a clean formula, and each step nudges `theta` a little way downhill:

```python
eta = 0.1                                 # learning rate = how big each step is
n_epochs = 1000                           # how many steps to take
theta = rng.standard_normal((2, 1))       # start from a random line

for epoch in range(n_epochs):
    gradients = 2 / m * X_b.T @ (X_b @ theta - y)   # which way is downhill (for both params)
    theta = theta - eta * gradients                 # take a step that way

print(theta.ravel())          # → the same ~[3.9, 3.0] the normal equation found!
```

One full pass over the data is called an **epoch**. After enough epochs, `theta` settles at
the bottom of the bowl — the *same* answer as Route A. Gradient descent just walked there
instead of teleporting.

### Feel the learning rate

The learning rate `eta` is the one knob you'll tune constantly. It's exactly the
"learning rate" idea from the lesson:

- **Too small** → tiny steps, painfully slow to converge (try `eta = 0.001`).
- **Too large** → you overshoot the valley and bounce *up* the far side; the numbers blow
  up to `nan` (try `eta = 1.5`).
- **Just right** → converges in a handful of epochs.

```python
for eta in (0.001, 0.1, 1.5):
    theta = rng.standard_normal((2, 1))
    for _ in range(50):
        theta = theta - eta * (2 / m * X_b.T @ (X_b @ theta - y))
    print(f"eta={eta}: theta={theta.ravel()}, cost={mse(X_b, y, theta):.3f}")
```

Watch the cost for each: small `eta` is still far off after 50 steps, big `eta` has diverged,
the middle one has nailed it. This exact trade-off shows up for **every** model you'll train.

> **Why this matters later:** the normal equation only works for linear regression. Gradient
> descent works for *anything* you can measure a cost and a slope on — logistic regression,
> neural networks, all of it. This little loop is the engine of modern ML in miniature.

## 5. The library way — scikit-learn

In real work you don't hand-roll any of the above. scikit-learn does it in three lines, and
it uses a numerically robust method (SVD) under the hood:

```python
from sklearn.linear_model import LinearRegression

lin_reg = LinearRegression()
lin_reg.fit(X, y)
print(lin_reg.intercept_, lin_reg.coef_)     # same bias and weight, ~[3.9] and ~[3.0]
```

Notice scikit-learn keeps the bias (`intercept_`) separate from the weights (`coef_`) — so
you *don't* prepend the column of 1s; `fit()` handles that. Predict on new sizes with
`lin_reg.predict([[1.5]])`.

For very large datasets where even that is too slow, scikit-learn's `SGDRegressor` runs
*stochastic* gradient descent (one example at a time) — the scaled-up cousin of the loop you
wrote in Route B.

