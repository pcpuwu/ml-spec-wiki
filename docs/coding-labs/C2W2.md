## 1. The activation zoo, from scratch

An **activation function** `g(z)` is the little non-linear kink applied to each neuron's
weighted sum `z = w·x + b`. The three the lesson names are one line each:

```python
def linear(z):   return z                    # "no activation" — g(z) = z
def sigmoid(z):  return 1 / (1 + np.exp(-z))  # squashes to (0, 1)
def relu(z):     return np.maximum(0, z)      # max(0, z) — flat below 0, 45° line above
```

```python
z = np.array([-3.0, -1.0, 0.0, 1.0, 3.0])
print("linear :", linear(z))    # [-3. -1.  0.  1.  3.]
print("sigmoid:", sigmoid(z).round(3))   # [0.047 0.269 0.5   0.731 0.953]
print("relu   :", relu(z))      # [0. 0. 0. 1. 3.]
```

Read off the ranges from the lesson: **linear** is unbounded `(−∞, ∞)`, **sigmoid** is capped
at `(0, 1)`, **ReLU** is `[0, ∞)` — flat `0` for negative inputs, then it just passes the input
through. That last property is why ReLU became the default hidden-layer choice: it's dirt cheap
(no exponential), and unlike sigmoid it's flat on *only one* side, so gradient descent doesn't
stall on a plateau.

### Why we need the non-linearity at all

Here's the argument Géron makes, in code. Stack two **linear** layers and you get… one linear
layer. The kink is the whole point.

```python
W1 = rng.standard_normal((3, 4))     # layer 1: 3 inputs → 4 units
W2 = rng.standard_normal((4, 2))     # layer 2: 4 units  → 2 outputs
x  = rng.standard_normal(3)

two_linear_layers = (x @ W1) @ W2        # no activation between them
one_equivalent    = x @ (W1 @ W2)        # ... collapses to a single matrix
print(np.allclose(two_linear_layers, one_equivalent))   # True
```

Two linear layers are *exactly* one linear layer (`W1 @ W2` is just another matrix). No matter
how many you stack, without a non-linearity in between the whole network can only draw a
straight line. Slotting a ReLU (or sigmoid) between the layers is what lets a deep net bend
into complex shapes.

## 2. Choosing an activation — match the output to the label

Hidden layers are easy: **use ReLU**. The interesting choice is the **output** layer, and it's
driven entirely by what your target `y` can be (straight from the lesson):

| If `y` is… | Output activation | Why |
|---|---|---|
| `0` or `1` (binary) | **sigmoid** | output = `P(y=1)` |
| any value, `±` (e.g. price change) | **linear** | `g(z)` can be negative |
| `≥ 0` only (e.g. a house price) | **ReLU** | never negative |
| one of `K` classes (multiclass) | **softmax** | a probability *per class*, summing to 1 |

That last row is this week's new tool. Let's build it.

---

## 3. Softmax, from scratch

Softmax generalises the sigmoid from two classes to `K`. Compute one score `zⱼ` per class,
then exponentiate-and-normalise so the outputs are positive and sum to `1`:

$$a_j = \frac{e^{z_j}}{\sum_{k=1}^{K} e^{z_k}} = P(y = j \mid x)$$

The naive translation is one line:

```python
def softmax_naive(z):
    e = np.exp(z)
    return e / e.sum()

print(softmax_naive(np.array([1.0, 2.0, 3.0])).round(3))   # [0.09 0.245 0.665]  → sums to 1
```

### The numerical-stability fix

The lesson on the *improved* softmax warned that `e^{zⱼ}` blows up for large `z` — and that's
not hypothetical:

```python
print(softmax_naive(np.array([1000.0, 1001.0, 1002.0])))   # [nan nan nan] — exp() overflowed
```

The fix is a one-line identity: subtracting a constant from every score leaves the softmax
**unchanged** (the constant cancels top and bottom), so subtract the max to force the largest
exponent to `e^0 = 1`:

```python
def softmax(z):
    z = z - z.max(axis=-1, keepdims=True)    # shift so the biggest logit is 0 — same result, no overflow
    e = np.exp(z)
    return e / e.sum(axis=-1, keepdims=True)

print(softmax(np.array([1000.0, 1001.0, 1002.0])).round(3))   # [0.09 0.245 0.665] — identical, no nan
```

The `axis=-1, keepdims=True` makes this work row-wise on a whole batch of logits at once. **This**
is the version to use — same math, no overflow. It's exactly why frameworks fold the softmax
into the loss (`from_logits=True` in Keras, `CrossEntropyLoss` in PyTorch): they rearrange the
terms internally to dodge those extremes.

## 4. The cross-entropy loss, from scratch

Softmax gives probabilities; the loss says how good they are. For the true class `j`, the
cross-entropy loss is just `−log aⱼ` — small when the model is confident and right, large when
it's confident and wrong:

```python
def cross_entropy(probs, y):
    m = len(y)
    correct = probs[np.arange(m), y]        # pick each row's true-class probability
    return -np.mean(np.log(correct + 1e-12))   # +tiny to avoid log(0)

probs = np.array([[0.7, 0.2, 0.1],   # example 0, true class 0 → confident & right → low loss
                  [0.1, 0.2, 0.7]])  # example 1, true class 0 → confident & wrong → high loss
print(cross_entropy(probs, y=np.array([0, 0])).round(3))   # 1.328
```

The curve `−log a` is near `0` when `a → 1` and shoots up as `a → 0`, so minimising it pushes
the probability of the *correct* class toward 1.

## 5. Back-prop by hand — the computation graph

Now the heart of it. Back-prop is how frameworks get the gradients — and it's nothing more than
the **chain rule applied right-to-left** across a computation graph. Let's do the lesson's exact
tiny example by hand, then check it.

One linear unit `a = wx + b` with squared-error cost `J = ½(a − y)²`, on a single example
`x = −2, y = 2`, starting at `w = 2, b = 8`.

**Forward pass** (left → right) — break it into named intermediate nodes:

```python
x, y, w, b = -2.0, 2.0, 2.0, 8.0

c = w * x          # -4
a = c + b          #  4
d = a - y          #  2
J = 0.5 * d**2     #  2.0
print(c, a, d, J)  # -4.0 4.0 2.0 2.0
```

**Backward pass** (right → left) — at each node ask "if I nudge this up by ε, how much does `J`
move?" Each answer is the previous answer times the local derivative (the chain rule):

```python
dJ_dd = d                # J = ½d²  → dJ/dd = d = 2
dJ_da = dJ_dd * 1        # d = a - y → local slope 1
dJ_dc = dJ_da * 1        # a = c + b → local slope 1  (b passes straight through too)
dJ_db = dJ_da * 1        # a = c + b → dJ/db = 2
dJ_dw = dJ_dc * x        # c = w·x   → local slope x = -2

print("dJ/dw =", dJ_dw)  # -4.0
print("dJ/db =", dJ_db)  #  2.0
```

That `dJ/dw = −4` matches the lesson exactly. Notice the efficiency the lesson emphasised:
`dJ_da` was computed **once** and reused for *both* `dJ/dw` and `dJ/db`. Going right-to-left,
every shared sub-result is computed a single time — that's why back-prop scales to millions of
parameters.

### Gradient check — prove it's right

Don't trust hand-derived gradients; check them against the definition of a derivative (nudge
`w` by a tiny `ε` and re-measure `J`):

```python
def J_of_w(w_):
    return 0.5 * (w_ * x + b - y) ** 2

eps = 1e-6
numeric = (J_of_w(w + eps) - J_of_w(w - eps)) / (2 * eps)
print(numeric)     # ≈ -4.0 — matches dJ_dw
```

If the numeric and analytic gradients agree, your back-prop is correct. This is the single most
useful debugging trick you'll learn this course.

## 6. A softmax classifier, trained from scratch

Chain sections 3–5 together and you have a trainable model. For a one-layer softmax classifier,
the forward pass is `logits → softmax → cross-entropy`, and the whole back-prop collapses to one
beautiful line: the gradient of cross-entropy-with-softmax with respect to the logits is just
**`(predicted probs − one-hot truth)`**. No messy exp's survive — they cancel.

```python
from sklearn.datasets import make_blobs

X, y = make_blobs(n_samples=300, centers=3, n_features=2, random_state=42)
X = (X - X.mean(0)) / X.std(0)          # standardize features
m, n = X.shape
K = 3
Y = np.eye(K)[y]                        # one-hot targets, shape (m, K)

W = rng.standard_normal((n, K)) * 0.01  # weights, one column per class
b = np.zeros(K)

eta = 0.5
for epoch in range(500):
    logits = X @ W + b                  # (m, K)
    probs  = softmax(logits)            # our stable softmax from §3
    loss   = -np.mean(np.sum(Y * np.log(probs + 1e-12), axis=1))

    dlogits = (probs - Y) / m           # ← the whole gradient, in one line
    dW = X.T @ dlogits                  # (n, K)
    db = dlogits.sum(axis=0)            # (K,)

    W -= eta * dW                       # gradient-descent step
    b -= eta * db

acc = (softmax(X @ W + b).argmax(1) == y).mean()
print(f"final loss {loss:.3f}, train accuracy {acc:.1%}")   # near-zero loss, ~100% (blobs separate cleanly)
```

That's a complete neural-network training loop in ten lines — forward pass, loss, back-prop,
update — no framework. The `(probs - Y)` gradient is the same object PyTorch's autograd computes
for you in the next section; you've just done it by hand once so you know it's not magic.

## 7. The library way — PyTorch

In real work you don't hand-derive gradients — you declare the network and let **autograd**
run back-prop, and let **Adam** adapt the step size per parameter. Here's the same multiclass
job on the Iris dataset (3 flower species), the way you'd actually write it.

```python
import torch
import torch.nn as nn
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

iris = load_iris()
Xtr, Xte, ytr, yte = train_test_split(iris.data, iris.target, test_size=0.33, random_state=1)

mu, sd = Xtr.mean(0), Xtr.std(0)                          # standardize with TRAIN stats only
Xtr = torch.tensor((Xtr - mu) / sd, dtype=torch.float32)
Xte = torch.tensor((Xte - mu) / sd, dtype=torch.float32)
ytr = torch.tensor(ytr)                                   # int64 class indices
yte = torch.tensor(yte)

model = nn.Sequential(
    nn.Linear(4, 16), nn.ReLU(),      # hidden layers: ReLU (the default from the lesson)
    nn.Linear(16, 16), nn.ReLU(),
    nn.Linear(16, 3),                 # output: 3 raw logits — NO softmax here (see below)
)

loss_fn   = nn.CrossEntropyLoss()                          # folds softmax IN — the from_logits trick
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)  # Adam: the de-facto default optimizer

for epoch in range(200):
    logits = model(Xtr)               # forward pass
    loss   = loss_fn(logits, ytr)     # softmax + cross-entropy, numerically stable
    optimizer.zero_grad()             # clear last step's gradients
    loss.backward()                   # back-prop — autograd fills in every gradient
    optimizer.step()                  # Adam updates every parameter

with torch.no_grad():
    acc = (model(Xte).argmax(1) == yte).float().mean()
print(f"test accuracy {acc:.1%}")     # ~96%
```

Three things map straight back to the lessons:

- **ReLU on the hidden layers, nothing on the output.** The final `nn.Linear` emits raw
  **logits**, not probabilities — deliberately.
- **`CrossEntropyLoss` expects logits.** It applies log-softmax *inside* the loss — exactly the
  numerically-stable `from_logits=True` recipe from the improved-softmax lesson. Putting your own
  `nn.Softmax` before it would apply softmax **twice** (a bug — see Your Turn #4). To read actual
  probabilities at predict time, run the logits through `torch.softmax(logits, dim=1)` yourself.
- **`Adam`** replaces plain gradient descent. It keeps a separate, self-adjusting learning rate
  per parameter — speeding up parameters that move steadily, calming ones that oscillate — which
  is why it trains faster and is the safe default.

The four-line loop (`zero_grad → backward → step`) is *the* PyTorch training loop; you'll write
it, essentially unchanged, for every model from here on. `loss.backward()` is running the exact
right-to-left computation-graph pass you did by hand in §5 — just automatically, over thousands
of parameters.

**5. Gradient-check the from-scratch classifier.** Pick one weight in §6's `W`, nudge it by

??? success "Solution"
    ```python
    def loss_at(W_):
        p = softmax(X @ W_ + b)
        return -np.mean(np.sum(Y * np.log(p + 1e-12), axis=1))

    eps = 1e-5
    Wp, Wm = W.copy(), W.copy()
    Wp[0, 0] += eps; Wm[0, 0] -= eps
    numeric = (loss_at(Wp) - loss_at(Wm)) / (2 * eps)
    print(numeric, dW[0, 0])   # ≈ equal — the analytic (probs - Y) gradient is correct
    ```
