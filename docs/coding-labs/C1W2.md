Week 1 fit a line through one feature. This week does three things that turn that toy into
the workhorse you'll actually use: predict from **many features** at once (one dot product),
**scale** those features so gradient descent stops crawling, and bend the straight line into
a **curve** by feeding it powers of a feature. We'll build each from scratch in NumPy so you
see the math become code, then reach for the scikit-learn one-liner you'd type on the job.

The through-line: everything here is *still* linear regression. More features, scaled
features, and polynomial features are all just different columns handed to the same
`w · x + b` engine from last week.

## 0. Setup and some data

We'll predict house price from **two** features on wildly different scales — square footage
(hundreds to thousands) and bedroom count (1–5) — plus noise, from a known formula so we can
check our answers.

```python
import numpy as np

rng = np.random.default_rng(42)              # fixed seed → reproducible "random" data
m = 100                                       # number of training examples

size     = rng.uniform(300, 2000, m)          # feature 1: sq ft — a big range
bedrooms = rng.integers(1, 6, m).astype(float)  # feature 2: 1–5 — a tiny range
X = np.column_stack([size, bedrooms])         # shape (m, 2): one row per house

true_w, true_b = np.array([0.15, 20.0]), 50.0  # the formula we'll try to recover
y = X @ true_w + true_b + rng.standard_normal(m) * 10
```

`X` is now `m` rows × `n = 2` columns. In the lesson's notation each row is `x⁽ⁱ⁾` (the vector
of features for one house) and `x⁽ⁱ⁾ⱼ` is feature `j` of example `i`. The two features spanning
very different ranges — 300–2000 vs. 1–5 — is exactly the setup that makes scaling matter later.

## 1. The model with many features is one dot product

The lesson's multiple-feature model is

$$f_{\vec{w},b}(\vec{x}) = w_1 x_1 + w_2 x_2 + \dots + w_n x_n + b = \vec{w}\cdot\vec{x} + b.$$

That weighted sum **is** a dot product. You could compute it three ways — spelled out term by
term, in a `for` loop, or **vectorized** in one line — and only the last one scales:

```python
w = np.array([0.15, 20.0])
b = 50.0
x = X[0]                                   # one house

term_by_term = w[0]*x[0] + w[1]*x[1] + b   # fine for n=2, hopeless for n=100,000
loop         = sum(w[j]*x[j] for j in range(len(w))) + b
vectorized   = np.dot(w, x) + b            # the one you actually write
print(term_by_term, loop, vectorized)      # all identical
```

`np.dot` (or the `@` operator) hands the whole sum to NumPy's optimized linear-algebra
routines, which use your CPU/GPU's parallel hardware instead of stepping through one term at a
time in Python. For the **whole dataset** at once it's a single matrix multiply:

```python
def predict(X, w, b):
    return X @ w + b        # ŷ for every row, in one shot

print(predict(X, w, b)[:5])   # first five predicted prices
```

### See why vectorization wins

Not a style preference — it's a speed cliff. Time the loop against the dot product on a
million-element vector:

```python
import time
n = 1_000_000
big_w, big_x = rng.random(n), rng.random(n)

t = time.perf_counter()
s = sum(big_w[j]*big_x[j] for j in range(n))
print(f"python loop: {time.perf_counter()-t:.4f}s")

t = time.perf_counter()
s = np.dot(big_w, big_x)
print(f"np.dot     : {time.perf_counter()-t:.4f}s")   # typically ~100× faster
```

Same math, two orders of magnitude apart. Every model you train from here on leans on this.

## 2. Gradient descent for many features, from scratch

Last week's gradient-descent loop already generalizes to `n` features with almost no change —
the gradient formula is identical, it just runs over every column at once. We'll keep the bias
`b` separate from the weights `w` (that's how the lessons and scikit-learn both do it):

```python
def gradient_descent(X, y, eta, n_epochs):
    m, n = X.shape
    w, b = np.zeros(n), 0.0
    for _ in range(n_epochs):
        err = X @ w + b - y                # residual for every example, shape (m,)
        w  -= eta * (2 / m) * (X.T @ err)  # one gradient step for all n weights
        b  -= eta * (2 / m) * err.sum()    # ... and the bias
    return w, b
```

Now try to train it on the **raw** features and watch it fall apart:

```python
w, b = gradient_descent(X, y, eta=1e-2, n_epochs=1000)
print(w, b)        # → nan nan ... : it diverged
```

`nan`. The size column (up to 2000) makes its slice of the gradient enormous, so a learning
rate the bedroom column can tolerate sends the size weight rocketing off to infinity. You *can*
rescue it by shrinking `eta` until the biggest feature behaves —

```python
w, b = gradient_descent(X, y, eta=1e-7, n_epochs=100_000)
print(w, b)        # crawls toward the answer, but needs a tiny step + tons of epochs
```

— but now the step is so small that the bedroom weight barely moves. That's the tall-skinny-
contour problem from the lesson: one learning rate can't suit both scales at once. The fix
isn't a cleverer `eta`, it's making the features comparable.

## 3. Feature scaling from scratch — z-score normalization

The lesson gives three recipes (divide-by-max, mean normalization, z-score). The one the
assignments and every library default to is **z-score / standardization**: subtract each
feature's mean, divide by its standard deviation, so every column ends up centered at 0 with
spread 1.

$$x'_j = \frac{x_j - \mu_j}{\sigma_j}$$

Done per column, it's four lines of NumPy:

```python
def zscore(X):
    mu    = X.mean(axis=0)      # per-column mean   → shape (n,)
    sigma = X.std(axis=0)       # per-column stddev → shape (n,)
    return (X - mu) / sigma, mu, sigma

X_scaled, mu, sigma = zscore(X)
print(X_scaled.mean(axis=0).round(6), X_scaled.std(axis=0).round(6))  # ≈ [0 0]  [1 1]
```

Return `mu` and `sigma`, not just the scaled matrix — you need the **exact same** shift and
scale to transform any future house before predicting (never re-fit them on new data). Now the
identical gradient-descent loop, same `eta`, converges almost instantly:

```python
w_s, b_s = gradient_descent(X_scaled, y, eta=0.1, n_epochs=1000)
print(w_s, b_s)     # converges fast — no nan, no 100k epochs
```

One learning rate now suits both weights because both features live on the same scale — the
skinny contours became round, and gradient descent walks straight to the bottom. The weights
`w_s` are in *scaled* space, so to predict a new house you scale it with the stored `mu`/`sigma`
first:

```python
new_house = np.array([[1500, 3]])                 # 1500 sq ft, 3 bedrooms
pred = ((new_house - mu) / sigma) @ w_s + b_s
print(pred)                                        # price in the same units as y
```

## 4. The library way — StandardScaler

In real code you don't hand-roll `zscore`; scikit-learn's `StandardScaler` is the exact same
math with `fit` (learn `mu`/`sigma` from the training set) and `transform` (apply them)
separated so you can't accidentally leak the test set into your scaling:

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)        # learns + applies mean/std in one call
print(scaler.mean_, scaler.scale_)        # the same mu and sigma you computed by hand
```

**Fit on training data only.** Once fitted, call `scaler.transform(X_new)` on validation, test,
or live data — reusing the training `mu`/`sigma`, exactly like passing your stored values
around above. Géron's warning: never call `fit()` on anything but the training set.

scikit-learn also ships `MinMaxScaler` (the divide-to-a-range recipe, default 0–1). Reach for
`StandardScaler` by default — it's far less rattled by outliers, since one bad value can't crush
every other value into a sliver the way min-max rescaling can.

## 5. Polynomial regression from scratch — powers as features

A straight line can't follow curved data. The trick: **manufacture new features by raising an
existing one to powers**, then hand them to the same linear model. That's polynomial
regression — still linear in the *parameters*, just fed nonlinear columns.

Generate curved data from a quadratic, the way Géron does:

```python
m = 200
x = rng.uniform(-3, 3, (m, 1))                        # one feature
y = 0.5 * x[:, 0]**2 + x[:, 0] + 2 + rng.standard_normal(m)   # quadratic + noise
```

Now build the extra column by hand — stack `x` and `x²` side by side — and you've turned a
one-feature problem into a two-feature one that a plain line can fit:

```python
X_poly = np.column_stack([x[:, 0], x[:, 0]**2])       # features: [x, x²]
```

**Feature scaling is now essential, not optional.** If `x` spans a few units, `x²` spans its
square and higher powers explode further — wildly different scales, the exact thing that broke
gradient descent in §2. So scale, then fit (we'll reuse the closed-form normal equation from
last week's lab since it needs no learning rate):

```python
X_poly_scaled, mu, sigma = zscore(X_poly)
X_b = np.c_[np.ones((m, 1)), X_poly_scaled]           # prepend the bias column
theta = np.linalg.inv(X_b.T @ X_b) @ X_b.T @ y        # normal equation
print(theta)          # bias, then weights on the (scaled) x and x² columns
```

The model has recovered the curve — it learned to weight the `x²` column heavily because the
data really was quadratic. Powers aren't the only choice: a `√x` feature (`np.sqrt`) fits a
shape that rises then flattens without ever turning back down, as the lesson notes.

## 6. The library way — PolynomialFeatures in a pipeline

scikit-learn generates the power columns for you with `PolynomialFeatures`, and a **pipeline**
chains "make powers → scale → fit" into one object so you never scale the wrong split or forget
a step:

```python
from sklearn.preprocessing import PolynomialFeatures
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LinearRegression

model = make_pipeline(
    PolynomialFeatures(degree=2, include_bias=False),   # adds x², (and cross-terms if >1 feature)
    StandardScaler(),                                    # scales every generated column
    LinearRegression(),
)
model.fit(x, y)
lin = model.named_steps["linearregression"]
print(lin.intercept_, lin.coef_)     # ≈ the 2, 1, 0.5 that generated the data
```

`fit`/`predict` on the whole pipeline runs all three steps in order — `model.predict(x_new)`
makes the powers, scales them with the training statistics, and applies the weights, all
automatically. With multiple input features, `PolynomialFeatures(degree=d)` also adds every
*cross-term* (`x₁x₂`, `x₁²x₂`, …), which plain linear regression can't discover on its own —
handy, but the column count blows up fast, so keep `degree` small.

### How much curve is too much

More powers always fit the *training* data better — a high enough degree can thread every point
— but that's memorizing noise, not learning the pattern (**overfitting**, which Week 3 tackles).
Géron's tool for spotting it is the **learning curve**: train on growing slices of data and plot
train vs. validation error.

```python
from sklearn.model_selection import learning_curve

for degree in (2, 15):
    pipe = make_pipeline(PolynomialFeatures(degree, include_bias=False),
                         StandardScaler(), LinearRegression())
    sizes, train_sc, val_sc = learning_curve(
        pipe, x, y, train_sizes=np.linspace(0.1, 1.0, 10), cv=5,
        scoring="neg_root_mean_squared_error")
    gap = (-val_sc.mean(axis=1))[-1] - (-train_sc.mean(axis=1))[-1]
    print(f"degree {degree:2d}: train–valid gap = {gap:.2f}")   # degree 15's gap is much wider
```

A big gap between the curves — great on train, worse on validation — is the fingerprint of
overfitting. Degree 2 (the true shape) keeps them close; degree 15 pulls them apart.
