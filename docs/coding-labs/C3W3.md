Everything this week hangs off **one equation** — the Bellman equation:

$$Q(s, a) = R(s) + \gamma \max_{a'} Q(s', a').$$

The Q-value of "do action $a$ in state $s$" is the reward you get, plus a discounted dose of
the best you can do from wherever you land. That's it. In this lab we turn that line of
algebra into three programs, from the inside out:

1. **Value iteration** — when you *know* how the world works, sweep the Bellman equation
   over every state until the numbers stop moving. Exact, model-based.
2. **Tabular Q-learning** — when you *don't* know the world, wander around and let each
   experience nudge one cell of a Q-table. Model-free, and the actual RL algorithm.
3. **A Deep Q-Network (DQN)** — when the states are too many to tabulate, swap the table
   for a neural net. Same Bellman target, now a regression problem.

We'll build all three on Ng's **Mars rover** — the six-cell line from the lectures — so the
numbers stay small enough to check by hand. A line of cells is the simplest possible
**gridworld**; everything here scales straight up to the 2-D versions and the lunar lander.

---

## 0. The world, as a tiny environment

The rover lives on six cells. The far-left cell pays **+100**, the far-right pays **+40**,
the four in between pay **0**. The two ends are **terminal** — reach one, collect the reward,
day over. Two actions: `LEFT` and `RIGHT`. We index the states `0..5`, so state 0 is the
+100 end and state 5 is the +40 end.

```python
import numpy as np

n_states  = 6
LEFT, RIGHT = 0, 1
n_actions = 2

reward   = np.array([100., 0., 0., 0., 0., 40.])          # reward for ARRIVING in each cell
terminal = np.array([True, False, False, False, False, True])
gamma    = 0.5                                             # discount (Ng's easy-arithmetic value)

def next_state(s, a):
    return s - 1 if a == LEFT else s + 1                  # LEFT = one cell left, RIGHT = one right
```

One design choice worth flagging: we pay the reward **when the rover arrives** in a cell, and
end the episode the moment it lands on a terminal. (Ng's slides instead credit the reward of
the cell you're *sitting in*, which prints Q-values a factor of $1/\gamma$ larger — the
**ranking of actions is identical**, which is all that decides the policy. We use the
arrival convention because it's the standard one and it's what the model-free code below
actually observes.)

## 1. The Bellman equation as code

The equation reads "reward now, plus $\gamma$ times the best future." Written for a single
`(s, a)` where the action lands you in `s_next`:

```python
def bellman_target(Q, s, a):
    s_next = next_state(s, a)
    future = 0.0 if terminal[s_next] else Q[s_next].max()   # max over a′ of Q(s′, a′)
    return reward[s_next] + gamma * future
```

`Q[s_next].max()` is exactly $\max_{a'} Q(s', a')$ — "the best I can do from the next state."
When `s_next` is terminal there is no future, so that term drops and the target is just the
reward. Every algorithm below is a different way of making `Q[s, a]` agree with this target.

---

## 2. Route A — value iteration (you know the world)

If you already know the rewards and where each action leads — as we do here — you don't need
to *learn* anything. You can compute $Q$ directly: start with a table of zeros and **sweep the
Bellman update over every state**, again and again. Each sweep pushes value one cell further
back from the rewards, like heat spreading out from the two ends. After a few passes the
numbers stop changing — that's the fixed point of the Bellman equation, the exact $Q^*$.

```python
Q = np.zeros((n_states, n_actions))

for sweep in range(100):
    Q_new = Q.copy()
    for s in range(n_states):
        if terminal[s]:
            continue                                  # terminal cells have no actions
        for a in (LEFT, RIGHT):
            Q_new[s, a] = bellman_target(Q, s, a)     # reward + γ·max future
    if np.allclose(Q_new, Q):
        print(f"converged after {sweep} sweeps")
        break
    Q = Q_new

print(np.round(Q, 2))
```

It converges in **4 sweeps**. The table:

```
        LEFT   RIGHT
state1  100.0   25.0
state2   50.0   12.5
state3   25.0   20.0
state4   12.5   40.0
```

Read a policy straight off it — in each state, take the action with the bigger number:

```python
V      = Q.max(axis=1)                                 # best return from each state
policy = np.where(Q.argmax(axis=1) == LEFT, "L", "R")
print("V     :", V[1:5])                               # [100. 50. 25. 40.]
print("policy:", policy[1:5])                          # ['L' 'L' 'L' 'R']
```

Exactly the lecture's punchline: **go left from the left half, but from state 4 (index 4) go
right** — it's close enough to the +40 that the near reward beats the discounted +100. The
best action genuinely depends on where you are. This is the [`argmax` policy read-off from
the theory](../course-3/week-3/state-action-value-function-definition.md), now in three lines.

So why ever do more? Because value iteration **cheats**: it uses `reward[...]` and
`next_state(...)` directly — a full map of the world. A real agent dropped into the rover
knows *neither*. It has to learn from experience.

## 3. Route B — tabular Q-learning (you don't know the world)

Now hide the map. The agent may only **act and observe**: take an action, see which cell it
lands in and what reward drops out. That's the honest RL setting. We wrap the (still-known-to-
*us*) dynamics in a `step` function that returns just those observations:

```python
def step(s, a):
    """Take action a in state s. Returns (next_state, reward, done) — nothing else."""
    s_next = next_state(s, a)
    return s_next, reward[s_next], terminal[s_next]
```

The agent keeps its **own** Q-table, starting at all zeros — a pure guess. Two ideas make it
learn:

**Explore vs. exploit (ε-greedy).** If the agent always took what it currently thinks is best,
a bad initial guess could stop it ever trying the good action. So with probability `epsilon`
it acts **randomly** (explore), otherwise it takes the current best (exploit). This is the
[ε-greedy policy from the theory](../course-3/week-3/bellman-equation.md).

```python
def choose_action(Q, s, epsilon, rng):
    if rng.random() < epsilon:
        return rng.integers(n_actions)     # explore: a random action
    return int(Q[s].argmax())              # exploit: best action so far
```

**The learning step.** After each `(s, a, r, s_next, done)`, we compute the Bellman target
and nudge the current estimate a fraction `alpha` of the way toward it — a running average
that smooths out the randomness:

$$Q(s, a) \leftarrow Q(s, a) + \alpha\,\big[\underbrace{r + \gamma \max_{a'} Q(s', a')}_{\text{target}} - Q(s, a)\big].$$

When the step ends the episode (`done`), there's no future, so the target is just `r`.

```python
def q_learning(episodes=3000, alpha=0.1, epsilon=0.2, seed=0):
    rng = np.random.default_rng(seed)
    Q = np.zeros((n_states, n_actions))
    for _ in range(episodes):
        s = rng.integers(1, 5)                          # start somewhere non-terminal
        while not terminal[s]:
            a = choose_action(Q, s, epsilon, rng)
            s_next, r, done = step(s, a)                 # only observations — no map!
            target = r if done else r + gamma * Q[s_next].max()
            Q[s, a] += alpha * (target - Q[s, a])        # nudge toward the target
            s = s_next
    return Q

Q_learned = q_learning()
print(np.round(Q_learned, 2))
print("policy:", np.where(Q_learned[1:5].argmax(axis=1) == LEFT, "L", "R"))
```

The learned table matches value iteration's **to the penny**, and recovers the same
`['L' 'L' 'L' 'R']` policy — except this agent was never handed the rewards or the layout. It
figured them out by bumping around. That's the whole magic of Q-learning: it learns the
optimal policy just by *watching itself act*, even while acting semi-randomly.

> **Why this matters:** value iteration needs a model of the world; Q-learning needs only the
> ability to try things and see what happens. That's what lets RL loose on games, robots, and
> the lunar lander, where nobody can write down `next_state(...)` in advance.

### Feel the knobs

RL is famously twitchy about its hyperparameters. Two to poke at:

- **`epsilon` too low** → the agent exploits a bad early guess and never discovers the good
  action; **too high** → it acts randomly forever and its policy is noisy. A common fix is to
  **start `epsilon` high and decay it** — explore early, exploit once the table is good.
- **`alpha` (learning rate)** trades speed for stability, exactly like gradient descent: too
  small learns slowly, too large makes the estimates jump around and never settle.

## 4. Route C — a Deep Q-Network, from scratch

Six states fit in a table. The lunar lander's state is **8 continuous numbers** — infinitely
many states, no table big enough. The fix ([from the theory](../course-3/week-3/learning-the-state-value-function.md)):
replace the lookup table `Q[s]` with a **neural network** $Q_\theta(s)$ that *predicts* the
Q-values for each action from the raw state. That's a **DQN**.

Everything else stays the same. The Bellman target is unchanged; we just turn "make the table
cell equal the target" into "**train the network so its output equals the target**" — an
ordinary regression with mean-squared-error loss. Two tricks from the DQN paper make it stable:

- **Replay buffer** — store the last few thousand `(s, a, r, s', done)` tuples and train on
  *random mini-batches* of them, so consecutive, correlated steps don't jerk the network around.
- **Bootstrapped targets** — the target uses the network's *own* current prediction of
  $\max_{a'} Q(s', a')$. It's a moving target that improves as the network does.

!!! note "Framework: PyTorch, not TensorFlow"
    Ng's lectures build the Q-network in TensorFlow/Keras. Below is **PyTorch**, the current
    industry-standard framework — the concepts (layers, an MSE loss, a Bellman target,
    backprop) are identical; only the syntax differs.

We'll keep using the rover so it's runnable and checkable, feeding the state to the net as a
**one-hot vector** (a stand-in for the lander's real-valued state):

```python
import torch
import torch.nn as nn
import random
from collections import deque

def encode(s):
    v = np.zeros(n_states, dtype=np.float32)
    v[s] = 1.0
    return v                                            # one-hot state → network input

# A DQN: state in, one Q-value out per action.
q_net = nn.Sequential(
    nn.Linear(n_states, 32), nn.ReLU(),
    nn.Linear(32, n_actions),
)
optimizer = torch.optim.Adam(q_net.parameters(), lr=1e-3)
buffer = deque(maxlen=5000)                             # the replay buffer (auto-drops oldest)
```

Choosing an action is ε-greedy again, but "best" now comes from a **forward pass** instead of
a table lookup:

```python
def choose_dqn_action(s, epsilon):
    if random.random() < epsilon:
        return random.randrange(n_actions)
    with torch.no_grad():
        q = q_net(torch.from_numpy(encode(s)))
    return int(q.argmax())
```

The training step samples a batch, builds Bellman targets, and takes **one gradient step** to
pull the predictions toward them:

```python
def train_step(batch_size=64):
    if len(buffer) < batch_size:
        return
    batch = random.sample(buffer, batch_size)
    s, a, r, s2, done = zip(*batch)
    s    = torch.from_numpy(np.stack(s))                     # (B, n_states)
    s2   = torch.from_numpy(np.stack(s2))
    a    = torch.tensor(a)
    r    = torch.tensor(r, dtype=torch.float32)
    done = torch.tensor(done, dtype=torch.float32)

    q_sa = q_net(s).gather(1, a[:, None]).squeeze(1)         # Q(s, a) the net predicts
    with torch.no_grad():
        max_next = q_net(s2).max(dim=1).values              # max_a′ Q(s′, a′)
    target = r + gamma * (1.0 - done) * max_next            # Bellman target (0 future if done)

    loss = nn.functional.mse_loss(q_sa, target)             # regression toward the target
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

And the full loop — play, remember, learn — is the [algorithm from the theory
lesson](../course-3/week-3/learning-the-state-value-function.md), line for line:

```python
epsilon = 1.0
for episode in range(2000):
    s = np.random.randint(1, 5)
    while not terminal[s]:
        a = choose_dqn_action(s, epsilon)
        s2, r, done = step(s, a)
        buffer.append((encode(s), a, r, encode(s2), done))   # store the experience
        train_step()                                          # learn from a random batch
        s = s2
    epsilon = max(0.05, epsilon * 0.995)                      # decay exploration over time

# Read the learned policy off the network:
with torch.no_grad():
    q_all = q_net(torch.from_numpy(np.stack([encode(s) for s in range(n_states)])))
print("policy:", np.where(q_all.argmax(1).numpy()[1:5] == LEFT, "L", "R"))
```

It rediscovers the same `['L' 'L' 'L' 'R']` — but now the policy lives in 32 hidden units and a
few hundred weights, not a table. That's the exact same object that flies the lunar lander;
the only differences there are a bigger network, more inputs, and a lot more patience.
