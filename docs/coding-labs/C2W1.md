Here's the one idea the whole week rests on: **a neuron is just a logistic-regression unit**,
and **a layer is a stack of them**. Once you believe that, a neural network is nothing exotic —
it's the `g(w·x + b)` you already know, repeated a few times, with the output of one layer
becoming the input to the next. That "run left to right, layer by layer" pass is **forward
propagation**.

We'll build it from the inside out:

1. **One neuron, by hand** — the literal `z = w·x + b`, `a = g(z)` from the lesson.
2. **A whole layer at once** — the same thing vectorized into one `matmul`, so 3 neurons cost the same code as 1.
3. **Stack the layers** — chain two `dense` calls and you have forward propagation through a real 2→3→1 network.
4. **The library way** — PyTorch's `nn.Sequential`, which is what you'd actually ship.

All four compute the exact same thing. Seeing that is the whole point.

## 0. Setup and some data

We'll reuse the course's **coffee-roasting** example: two features — roast **temperature** (°C)
and **duration** (minutes) — and the network predicts whether the beans come out good.

```python
import numpy as np

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))     # g(z), the logistic function from Course 1

x = np.array([200.0, 17.0])             # one example: 200°C for 17 minutes
```

`x` is a single training example with 2 features. That's `a⁽⁰⁾` in the lesson's notation —
the "activation" of layer 0, which is just the raw input.

Two features live on wildly different scales (200 vs 17), which makes the raw dot products
huge and saturates the sigmoid. Real networks **normalize** first, so let's do that — it makes
the activations land in an interesting range instead of pinned at 0 or 1:

```python
mu = np.array([200.0, 15.0])            # rough feature means
sd = np.array([15.0, 3.0])             # rough feature spreads
x_norm = (x - mu) / sd                  # → about [0.0, 0.67]
```

## 1. One neuron, by hand

Straight from the *Forward Prop in a Single Layer* lesson: a neuron takes the input vector,
dots it with its own weights, adds its bias, and squashes the result through the sigmoid.
Here's the **first unit of layer 1**, with its own `w` and `b`:

```python
w1_1 = np.array([ 1.5, -2.0]);  b1_1 = -0.5     # weights + bias for unit 1
z1_1 = np.dot(w1_1, x_norm) + b1_1              # net input:  z = w·x + b
a1_1 = sigmoid(z1_1)                            # activation: a = g(z)
print(a1_1)                                     # a single number in (0, 1)
```

That's it — that's a neuron. `z1_1` is the **net input** (the same weighted sum from linear
regression), and `a1_1` is the **activation**. The notation `w1_1` reads as $\vec{w}^{[1]}_1$:
*layer 1, unit 1*.

A layer of 3 neurons is just this, three times, each with its own parameters. Grouping the
three activations into one vector gives the layer's output `a⁽¹⁾`:

```python
w1_2 = np.array([-3.0,  4.0]);  b1_2 =  0.2
w1_3 = np.array([ 2.0,  1.0]);  b1_3 = -1.0

a1_2 = sigmoid(np.dot(w1_2, x_norm) + b1_2)
a1_3 = sigmoid(np.dot(w1_3, x_norm) + b1_3)

a1 = np.array([a1_1, a1_2, a1_3])               # the layer-1 activation vector
print(a1)                                       # 3 numbers, one per unit
```

This works, but writing out a line per neuron is exactly the tedium the lesson warns about.
A 25-unit layer would be 25 copies. Time to vectorize.

## 2. A whole layer at once — the vectorized `dense`

The trick from *Matrix Multiplication Code*: **stack every neuron's weights as the columns of
one matrix `W`**, and the whole layer becomes a single matrix multiply plus one bias add. No
loop over neurons.

```python
W1 = np.array([[ 1.5, -3.0,  2.0],      # column j = weights of unit j
               [-2.0,  4.0,  1.0]])     # shape: (n_inputs=2, n_units=3)
b1 = np.array([-0.5,  0.2, -1.0])       # one bias per unit, shape (3,)

def dense(a_in, W, b, g=sigmoid):
    z = a_in @ W + b                    # net inputs for ALL units at once
    return g(z)                         # activations for ALL units at once

a1_vec = dense(x_norm, W1, b1)
print(a1_vec)                           # identical to the a1 we built by hand
```

The `W1` I picked has exactly the per-neuron weights from Section 1 as its columns, so
`a1_vec` matches `a1` to the last decimal — the vectorized version is *the same computation*,
just written once instead of three times. One `dense` call handles a 3-unit layer or a
3000-unit layer with no code change, and `@` (matrix multiply) is the operation modern GPUs
are built to run fast.

!!! info "A note on the row-vs-column convention"
    The course slides write $Z = A^{\top}W + B$ because they picture the input as a **column**.
    In code it's cleaner to keep each example as a **row** — that's the TensorFlow/PyTorch
    convention — so we write `a_in @ W + b` with no transpose. Same numbers, one fewer `.T`.
    When you batch many examples, `a_in` becomes a `(n_examples, n_inputs)` matrix and this
    exact line still works — every example flows through in parallel.

## 3. Stack the layers — that's forward propagation

Now the payoff. A network is just layers where **each layer's output is the next layer's
input**. Our 2→3→1 coffee network is one hidden layer (`dense` above) feeding an output layer
with a single unit. Chaining the calls left-to-right *is* forward propagation:

```python
# Output layer: 1 unit, takes the 3 hidden activations as input
W2 = np.array([[ 3.0],                  # shape (n_inputs=3, n_units=1)
               [-4.0],
               [ 2.0]])
b2 = np.array([0.5])

def forward(x, W1, b1, W2, b2):
    a1 = dense(x,  W1, b1)              # layer 1: 2 features → 3 activations
    a2 = dense(a1, W2, b2)             # layer 2: 3 activations → 1 output
    return a2

y_hat = forward(x_norm, W1, b1, W2, b2)
print(y_hat)                            # a single probability in (0, 1)
```

That's a complete neural network making a prediction. Read `forward` top to bottom and you're
literally watching the activations *propagate forward*: `x → a¹ → a²`. For the digit network
in the lesson (64 → 25 → 15 → 1) you'd just add more `dense` lines — nothing else changes.

To turn the probability into a yes/no decision, threshold it at 0.5, exactly like logistic
regression:

```python
prediction = int(y_hat[0] >= 0.5)       # 1 = good roast, 0 = bad roast
print(prediction)
```

> **Why this is a big deal:** we never wrote a training loop. With the weights already set,
> forward propagation alone runs the network. This is exactly how you'd **download someone
> else's trained weights** and run inference on your own data. Learning those weights (back-
> propagation) is next week — but the prediction machinery is already complete.

## 4. The library way — PyTorch `nn.Sequential`

In practice you don't hand-roll `dense`. A neural network that's "just a stack of layers" maps
perfectly onto PyTorch's `nn.Sequential`, which chains modules: it feeds the input to the first,
its output to the second, and so on — forward propagation, done for you.

!!! note "Ng's lectures use TensorFlow; this lab uses PyTorch"
    The concepts are identical — a stack of dense layers with activations — only the library
    names differ. PyTorch is the de-facto industry and research standard today, so we build in
    it here. Wherever Ng writes `tf.keras.Sequential([Dense(3), Dense(1)])`, the PyTorch below
    is the same network.

```python
import torch
from torch import nn

model = nn.Sequential(
    nn.Linear(2, 3),      # hidden layer: 2 inputs → 3 units  (= our dense(x, W1, b1))
    nn.Sigmoid(),         # the activation g applied to layer 1
    nn.Linear(3, 1),      # output layer: 3 inputs → 1 unit
    nn.Sigmoid(),         # activation g applied to the output
)

x_t = torch.tensor([[0.0, 0.67]])       # one example, as a (1, 2) tensor (row = example)
with torch.no_grad():                   # inference only — no gradients needed
    y_hat_torch = model(x_t)
print(y_hat_torch)                       # a (1, 1) tensor: the probability
```

A few things worth noticing:

- **`nn.Linear(2, 3)` is our `dense`** — it holds a `(3, 2)` weight matrix and a `(3,)` bias,
  and computes `x @ W.T + b` when called. PyTorch initializes those weights **randomly**, so
  your number won't match Section 3 — it's an *untrained* network (real weights come from
  training).
- **The activation is its own module.** `nn.Linear` does only the linear `w·x + b`; the
  `nn.Sigmoid` after it applies `g`. Stacking them reproduces `a = g(w·x + b)`.
- **`model(x_t)` is the entire forward pass** — the same `x → a¹ → a²` chain you wrote by hand
  in Section 3, now one call.
- Real MLPs usually use **`nn.ReLU`** between hidden layers instead of sigmoid (faster to
  train, more on that next week); sigmoid stays natural on the final layer for a probability.

You can peek at the parameters PyTorch is holding — the shapes line up with our `W1`/`W2`:

```python
for name, p in model.named_parameters():
    print(name, tuple(p.shape))
# 0.weight (3, 2)   0.bias (3,)   2.weight (1, 3)   2.bias (1,)
```

??? success "Solution"
    ```python

    ```

**3. Make the network deeper.** Add a second hidden layer (3 units) to `forward` — a 2→3→3→1
network. You'll need a new `W_mid` of shape `(3, 3)` and a bias of shape `(3,)`.

??? success "Solution"
    ```python
    W_mid = np.array([[ 1.0, -1.0,  0.5],
                      [ 0.5,  2.0, -1.0],
                      [-1.0,  0.5,  1.0]])
    b_mid = np.array([0.0, 0.1, -0.2])

    def forward_deep(x):
        a1 = dense(x,  W1,    b1)
        a2 = dense(a1, W_mid, b_mid)   # extra layer, same dense()
        a3 = dense(a2, W2,    b2)
        return a3

    print(forward_deep(x_norm))        # still one probability out
    ```

**4. Swap the hidden activation to ReLU in PyTorch.** Change the first `nn.Sigmoid()` to
`nn.ReLU()` and re-run the forward pass. The output still comes out in (0, 1) because the final
layer is still a sigmoid.

??? success "Solution"
    ```python
    model_relu = nn.Sequential(
        nn.Linear(2, 3),
        nn.ReLU(),              # ← hidden activation changed
        nn.Linear(3, 1),
        nn.Sigmoid(),
    )
    with torch.no_grad():
        print(model_relu(x_t))  # different number, still a valid probability
    ```
