A model almost never works the first time. This whole week is about the *diagnostics* that
tell you **what to try next** instead of guessing — and every one of them is just a few
numbers you compute from held-out data. In this lab we'll build them from the inside out:

1. **Split the data three ways**, then measure error on each — by hand.
2. **Choose a model** (which polynomial degree) by its cross-validation error, and read
   **bias vs. variance** straight off `J_train` and `J_cv`.
3. **Plot learning curves** from scratch to decide whether more data would even help.
4. **The library way** — scikit-learn's `learning_curve`, `validation_curve`, `cross_val_score`.
5. **Metrics for skewed data** — build the confusion matrix, precision, recall, and F1 by
   hand, then slide the **precision/recall trade-off** with the decision threshold.

Pure NumPy + scikit-learn throughout.

## 0. Setup and some data

We'll generate data from a known **quadratic** — `y = 0.5·x² + x + 2` — plus noise. Because
we know the true shape is degree 2, we can watch our diagnostics correctly flag a straight
line as *too simple* and a degree-12 monster as *too complex*.

```python
import numpy as np

rng = np.random.default_rng(0)
m = 200
X = rng.uniform(-3, 3, size=(m, 1))                       # one feature, in [-3, 3]
y = 0.5 * X[:, 0]**2 + X[:, 0] + 2 + rng.standard_normal(m)   # quadratic + noise
```

`X` is a column of 200 inputs; `y` is the noisy target. The `standard_normal(m)` term is the
**irreducible error** — noise no model can ever fit away.

---

## 1. Split it three ways, from scratch

The lesson's fix for "the test set got contaminated" is a **three-way split**: train (~60%)
to *fit* parameters, cross-validation (~20%) to *choose* between models, and test (~20%)
touched only once at the very end to report the honest generalization number. Shuffle first
so each split is a fair sample:

```python
idx = rng.permutation(m)                                  # shuffle the row indices
n_train, n_cv = int(0.6 * m), int(0.2 * m)
tr = idx[:n_train]                                        # 60% → training
cv = idx[n_train:n_train + n_cv]                          # 20% → cross-validation
te = idx[n_train + n_cv:]                                 # 20% → test

X_train, y_train = X[tr], y[tr]
X_cv,    y_cv    = X[cv], y[cv]
X_test,  y_test  = X[te], y[te]
print(len(X_train), len(X_cv), len(X_test))               # → 120 40 40
```

That's the entire idea. The cross-validation set is the one you're *allowed* to peek at while
tuning; the test set is sealed until you've committed to a model.

## 2. A cost you can read off any model

To compare models we need one number per dataset: the **cost**. We'll use Ng's half-mean-
squared-error, evaluated **without** any regularization term (exactly as `J_train`, `J_cv`,
`J_test` are defined in the lesson):

```python
def J(model, X, y):
    err = model.predict(X) - y            # residual for each example
    return float(err @ err / (2 * len(y)))    # (1 / 2m) · Σ (f(x) − y)²
```

We just need something with a `.predict()`. Here's a from-scratch polynomial regressor: it
expands `x` into `x, x², …, x^d`, **standardizes** those columns (high powers explode in
magnitude otherwise), and solves the normal equation with `pinv` for stability:

```python
class PolyReg:
    def __init__(self, degree):
        self.degree = degree

    def _features(self, X):
        return np.hstack([X**p for p in range(1, self.degree + 1)])   # [x, x², …, x^d]

    def fit(self, X, y):
        Z = self._features(X)
        self.mu, self.sd = Z.mean(0), Z.std(0) + 1e-12                # column stats
        Zb = np.c_[np.ones(len(Z)), (Z - self.mu) / self.sd]         # standardize + bias col
        self.theta = np.linalg.pinv(Zb.T @ Zb) @ Zb.T @ y            # normal equation
        return self

    def predict(self, X):
        Z = (self._features(X) - self.mu) / self.sd                  # reuse TRAIN stats
        return np.c_[np.ones(len(Z)), Z] @ self.theta
```

The one subtlety worth noticing: `predict` reuses the mean and std learned during `fit`. You
standardize the CV and test data with the *training* statistics — never re-fit the scaler on
data you're evaluating, or you've leaked information.

## 3. Model selection by cross-validation error

Now the core loop from the *Model Selection* lesson. Fit each candidate degree `d` on the
**training** set, then score it on the **CV** set. Pick the `d` with the lowest `J_cv` — and
crucially, do **not** pick it by `J_test` (that would make `J_test` an optimistic, cheating
estimate):

```python
for d in range(1, 11):
    model = PolyReg(d).fit(X_train, y_train)
    print(f"d={d:2d}   J_train={J(model, X_train, y_train):.3f}   J_cv={J(model, X_cv, y_cv):.3f}")
```

```
d= 1   J_train=1.395   J_cv=1.340
d= 2   J_train=0.454   J_cv=0.622
d= 3   J_train=0.452   J_cv=0.612
d= 4   J_train=0.451   J_cv=0.609
d= 5   J_train=0.448   J_cv=0.594
...
d=10   J_train=0.435   J_cv=0.635
```

Look at the two columns. `J_train` keeps *falling* as the model gets more flexible — a more
complex model can always hug the training points tighter. But `J_cv` forms a **U**: high on
the left (degree 1 underfits), bottoming out in the low-degree middle, then creeping back up.
That U is the whole game. Pick its minimum, then — and only then — unseal the test set:

```python
best_d = min(range(1, 11), key=lambda d: J(PolyReg(d).fit(X_train, y_train), X_cv, y_cv))
final = PolyReg(best_d).fit(X_train, y_train)
print(f"chosen degree = {best_d}")
print(f"J_test = {J(final, X_test, y_test):.3f}   (the honest generalization estimate)")
```

The test number is fair precisely because the test set played no part in choosing `best_d`.

## 4. Diagnosing bias vs. variance — the decision rule

The lesson boils diagnosis down to two comparisons. Let's see all three regimes as raw
numbers:

```python
for d, X_t, y_t in [(1,  X_train,      y_train),        # underfit: too simple
                    (2,  X_train,      y_train),        # just right
                    (12, X_train[:15], y_train[:15])]:  # overfit: complex model, few points
    model = PolyReg(d).fit(X_t, y_t)
    print(f"d={d:2d}  J_train={J(model, X_t, y_t):8.3f}   J_cv={J(model, X_cv, y_cv):10.3f}")
```

```
d= 1  J_train=   1.395   J_cv=     1.340     ← high bias
d= 2  J_train=   0.454   J_cv=     0.622     ← just right
d=12  J_train=   0.140   J_cv= 39325.393     ← high variance
```

Read it exactly like the slide:

- **High bias (underfit)** — `J_train` is **high** and `J_cv` is high *and close to it*. The
  model can't even fit the data it trained on. (Degree 1: both ≈ 1.4.)
- **High variance (overfit)** — `J_cv` **≫** `J_train`. It aced the training points and
  flunked everything else. (Degree 12 on 15 points: `J_train` ≈ 0.14, `J_cv` wildly higher —
  that absurd number is a degree-12 curve extrapolating between sparse points.)
- **Just right** — both low. (Degree 2, the true shape.)

Two comparisons, and you know which direction to move: high bias → a *bigger* model / more
features; high variance → *simpler* model, more regularization, or more data (next section
tells you whether that last one will pay off).

## 5. Learning curves, from scratch

A learning curve plots error against **training-set size** `m_train`. It answers the
month-saving question: *would collecting more data actually help?* Build it by fitting on
growing prefixes of the training set and scoring each on the fixed CV set.

**High-bias model (a straight line on quadratic data):**

```python
for n in (10, 30, 60, 120):
    model = PolyReg(1).fit(X_train[:n], y_train[:n])
    print(f"n={n:3d}   J_train={J(model, X_train[:n], y_train[:n]):.3f}   J_cv={J(model, X_cv, y_cv):.3f}")
```

```
n= 10   J_train=0.752   J_cv=1.902
n= 30   J_train=1.350   J_cv=1.677
n= 60   J_train=1.397   J_cv=1.499
n=120   J_train=1.395   J_cv=1.340
```

`J_train` **rises** (a line fits 10 points more easily than 120), `J_cv` **falls**, and they
converge and **plateau** — both stuck around 1.4, far above the ~0.5 a good model reaches.
**Consequence: more data won't help.** The curves have already flattened; the gap is bias,
not data starvation. You need a better model, not a bigger dataset.

**High-variance model (degree 12):**

```python
for n in (15, 30, 60, 120):
    model = PolyReg(12).fit(X_train[:n], y_train[:n])
    print(f"n={n:3d}   J_train={J(model, X_train[:n], y_train[:n]):.3f}   J_cv={J(model, X_cv, y_cv):.3f}")
```

```
n= 15   J_train=0.140   J_cv=39325.393
n= 30   J_train=0.244   J_cv=0.769
n= 60   J_train=0.348   J_cv=0.748
n=120   J_train=0.424   J_cv=0.629
```

Now there's a big gap: low `J_train`, much higher `J_cv`. But watch the gap **shrink** as `n`
grows — `J_cv` marches down toward `J_train`. **Here more data *does* help.** That's the tell:
a high-variance gap that keeps closing means "keep collecting examples."

## 6. The library way — scikit-learn

You don't hand-roll splits and curves on the job. `train_test_split` carves off a test set;
`cross_val_score` runs k-fold cross-validation (every point serves as validation once —
sturdier than one fixed split); `learning_curve` and `validation_curve` produce the exact
plots above in one call.

```python
from sklearn.model_selection import (train_test_split, cross_val_score,
                                     learning_curve, validation_curve)
from sklearn.preprocessing import StandardScaler, PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline

# a degree-d polynomial regressor, standardized, as one object
def poly_model(degree):
    return make_pipeline(StandardScaler(),
                         PolynomialFeatures(degree, include_bias=False),
                         LinearRegression())
```

**k-fold cross-validation** — a more robust `J_cv` than a single split (note the sign: sklearn
*maximizes* a score, so MSE is returned negated):

```python
scores = cross_val_score(poly_model(2), X, y, cv=5, scoring="neg_mean_squared_error")
print("per-fold MSE:", np.round(-scores, 3), "  mean:", round(-scores.mean(), 3))
```

**Validation curve** — the U from Section 3, automated. Sweep the degree, get train and CV
error for each:

```python
degrees = [1, 2, 4, 8, 12]
train_s, valid_s = validation_curve(
    poly_model(1), X, y,
    param_name="polynomialfeatures__degree", param_range=degrees,
    cv=5, scoring="neg_mean_squared_error")
print("degree      :", degrees)
print("train MSE   :", np.round(-train_s.mean(1), 3))   # → [2.943 1.037 1.020 1.003 0.985]
print("valid MSE   :", np.round(-valid_s.mean(1), 3))   # → [2.978 1.066 1.055 1.074 1.136]
```

Valid MSE dips at degree 2 and creeps up by degree 12 — the same "pick the bottom of the U"
story, no loop written.

**Learning curve** — the Section 5 plot, automated. It retrains on growing subsets and
cross-validates each size:

```python
sizes, train_s, valid_s = learning_curve(
    poly_model(2), X, y,
    train_sizes=np.linspace(0.1, 1.0, 6), cv=5,
    scoring="neg_mean_squared_error")
print("sizes    :", sizes)
print("train MSE:", np.round(-train_s.mean(1), 3))
print("valid MSE:", np.round(-valid_s.mean(1), 3))
```

To *see* it, plot both means against `sizes` (`plt.plot(sizes, -train_s.mean(1))` and the
same for valid) — converging-and-plateaued means bias, a wide-but-closing gap means variance.

## 7. Skewed data: when accuracy lies

Switch to classification. When one class is **rare**, accuracy becomes worthless: the lesson's
rare-disease example shows a do-nothing `print("y=0")` scoring 99.5%. Let's reproduce that
trap with a heavily imbalanced dataset (~5% positives):

```python
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression

Xc, yc = make_classification(n_samples=5000, n_features=10, n_informative=6,
                             n_redundant=0, weights=[0.95, 0.05],
                             class_sep=1.0, random_state=1)
print("positive fraction:", round(yc.mean(), 4))                 # → 0.054

Xtr, Xte, ytr, yte = train_test_split(Xc, yc, test_size=0.3,
                                      stratify=yc, random_state=1)   # keep the ratio in both
clf = LogisticRegression(max_iter=5000).fit(Xtr, ytr)
yhat = clf.predict(Xte)

model_acc  = (yhat == yte).mean()
always_neg = (yte == 0).mean()                                   # the "print y=0" cheat
print(f"model accuracy  = {model_acc:.4f}")                      # → 0.9747
print(f"always-negative = {always_neg:.4f}")                     # → 0.9460
```

A 97.5% model that barely beats a program that never predicts the disease. Accuracy can't
tell them apart — so build the **confusion matrix** for the rare class `y=1`, by hand:

```python
tp = int(np.sum((yhat == 1) & (yte == 1)))   # said 1, was 1
fp = int(np.sum((yhat == 1) & (yte == 0)))   # said 1, was 0  (false alarm)
fn = int(np.sum((yhat == 0) & (yte == 1)))   # said 0, was 1  (missed it)
tn = int(np.sum((yhat == 0) & (yte == 0)))   # said 0, was 0
print(f"TP={tp}  FP={fp}  FN={fn}  TN={tn}")                     # → TP=46 FP=3 FN=35 TN=1416
```

**Precision** (when it cries "disease", how often is it right?) and **recall** (of the real
cases, how many did it catch?) — the two numbers accuracy was hiding:

```python
precision = tp / (tp + fp)
recall    = tp / (tp + fn)
f1        = 2 * precision * recall / (precision + recall)   # harmonic mean
print(f"precision = {precision:.3f}   recall = {recall:.3f}   F1 = {f1:.3f}")
# → precision = 0.939   recall = 0.568   F1 = 0.708
```

There's the real story: when the model says "positive" it's right 94% of the time, but it
only *finds* 57% of the actual positives. The `print("y=0")` cheat would have **zero** TP, so
its recall is 0 and F1 is 0 — instantly exposed. F1 is the **harmonic mean**, which (unlike a
plain average) stays low unless *both* precision and recall are high. scikit-learn agrees:

```python
from sklearn.metrics import confusion_matrix, precision_score, recall_score, f1_score

print(confusion_matrix(yte, yhat))                               # [[1416 3] [35 46]]  (rows=actual)
print(precision_score(yte, yhat), recall_score(yte, yhat), f1_score(yte, yhat))
```

Note sklearn's `confusion_matrix` lays rows out as *actual* classes and columns as *predicted*
(the transpose of the lesson's slide) — same four counts, different corner.

## 8. Trading off precision and recall

Logistic regression outputs a **probability**; the default rule predicts 1 when it's `≥ 0.5`.
That 0.5 is a knob. **Raise** it and you only flag the confident cases (↑ precision, ↓ recall);
**lower** it and you flag anything suspicious (↑ recall, ↓ precision). Sweep it by hand using
`predict_proba`:

```python
proba = clf.predict_proba(Xte)[:, 1]                     # P(y=1) for each test example
for t in (0.3, 0.5, 0.7):
    pred = (proba >= t).astype(int)
    p = precision_score(yte, pred, zero_division=0)
    r = recall_score(yte, pred)
    print(f"threshold={t}:   precision={p:.3f}   recall={r:.3f}")
```

```
threshold=0.3:   precision=0.855   recall=0.654     ← catch more, cry wolf more
threshold=0.5:   precision=0.939   recall=0.568
threshold=0.7:   precision=1.000   recall=0.481     ← only the sure things
```

That's the trade-off in three lines: as the threshold climbs, precision rises and recall
falls. Which point you pick is an **application judgment call**, *not* something cross-
validation chooses — a cheap, safe treatment for a dangerous disease argues for high recall
(low threshold); a costly, invasive one argues for high precision. `precision_recall_curve`
gives you every point on that trade-off at once, and `classification_report` prints the whole
per-class table:

```python
from sklearn.metrics import precision_recall_curve, classification_report

precisions, recalls, thresholds = precision_recall_curve(yte, proba)
# plot precisions vs recalls to see the full trade-off frontier

print(classification_report(yte, yhat, digits=3))
```

The report's row for class `1` restates our by-hand precision 0.939 / recall 0.568 / F1 0.708
— now you know exactly where each number came from.
