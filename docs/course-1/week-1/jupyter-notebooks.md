To understand these ideas deeply you should *see code run* — and the tool for that
is the **Jupyter notebook**, the most widely used environment among machine-learning
and data-science practitioners. It's the same environment used inside many large
companies, not a simplified teaching toy, and it runs right in your browser.
`[00:21]`

## Two kinds of lab `[00:57]`

- **Optional labs** — open and run one line at a time, usually with **no code to
  write yourself.** They're guaranteed full marks (there are no marks) — you just run
  the provided code to see what ML code actually looks like. Optional, but worth
  doing for the feel. `[01:19]`
- **Practice labs** — start *next week*, and there you'll **write some of the code
  yourself.** `[01:58]`

## Two kinds of cell `[02:34]`

A notebook is made of **cells** of two types:

- **Markdown cells** — formatted text describing the code (editable; press
  **Shift+Enter** to render them back to formatted text).
- **Code cells** — runnable Python; press **Shift+Enter** to execute. `[03:11]`

Ng's suggested rhythm: select a cell, **read the code, predict what it will do, then
Shift+Enter** and see whether you were right. Feel free to edit the code and re-run
to see what changes. `[03:34]`

> In *this* wiki you get the same idea without leaving the page — the runnable code
> cells embedded in topics (like the cost-function exercise) execute Python in your
> browser, and the real graded assignments run locally via `/practice`.
