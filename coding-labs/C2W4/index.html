    C2 · W4 — Decision Trees, Random Forests & Boosting, in Code¶

    Recommended before this lab

    You'll get the most out of this once you've watched the Course 2 · Week 4 lessons that the code builds on — what a tree is, how it measures purity, how it picks a split, and the two ensembles that make trees win competitions:

    • Decision Tree Model
    • Measuring Purity → Choosing a Split: Information Gain
    • Random Forest Algorithm → XGBoost

    Not strict prerequisites — do the lab in whatever order you like — but this is the theory it turns into code.

    A decision tree is just a game of 20 questions: keep asking the single most informative yes/no question until you're confident of the answer. The whole trick is defining "most informative" as a number the computer can optimize. Let's build it from the inside out:

    1. From scratch — write the impurity and information-gain formulas from the lessons as a few lines of NumPy, then use them to find the best question to ask (a one-node tree).
    2. The library way — DecisionTreeClassifier, which does exactly that recursively.
    3. The ensembles — see one tree overfit, then fix it two ways: random forests (many trees vote) and boosting / XGBoost (each tree fixes the last one's mistakes). Both are what you'd actually reach for on the job.

    The from-scratch part uses the cat dataset from the lessons so the numbers match what you saw on the slides. The library part switches to a 2-D dataset so you can watch trees overfit.

    0. Setup and some data¶

    First, the cat dataset from the lesson — 10 animals, three binary features (ear shape pointy=1/floppy=0, face shape round=1/not=0, whiskers present=1/absent=0), and the label y = "is it a cat?". Five cats, five dogs:

    import numpy as np

#            ear face whisk
X = np.array([[1,  1,  1],    # cat
              [0,  0,  1],    # cat
              [0,  1,  0],    # dog
              [1,  0,  1],    # dog
              [1,  1,  1],    # cat
              [1,  1,  0],    # cat
              [0,  0,  0],    # dog
              [1,  1,  0],    # cat
              [0,  1,  0],    # dog
              [0,  1,  0]])   # dog
y = np.array([1, 1, 0, 0, 1, 1, 0, 1, 0, 0])
feature_names = ["ear shape", "face shape", "whiskers"]

    The root has 5 cats out of 10, so p₁ = 0.5 — a perfect 50/50 mix, the most impure a set can be. Our job is to ask questions that carve out purer subsets.

    1. Measuring purity from scratch¶

    To choose splits by purity you need to quantify it. The lesson's tool is entropy: a number that's 0 when a set is all one class (pure) and peaks at 1 for a 50/50 mix. With p₁ the fraction of cats and p₀ = 1 − p₁, the formula from the slide is

    \[H(p_1) = -p_1\log_2 p_1 - (1-p_1)\log_2(1-p_1),\]

    which is a direct transcription into NumPy:

    def entropy(y):
    if len(y) == 0:
        return 0.0
    p1 = y.mean()                       # fraction of class 1 (cats)
    if p1 == 0 or p1 == 1:
        return 0.0                      # pure set: convention 0·log0 = 0
    return -p1 * np.log2(p1) - (1 - p1) * np.log2(1 - p1)

print(entropy(y))                       # → 1.0, the 50/50 root is maximally impure
print(entropy(np.array([1, 1, 1])))     # → 0.0, all cats: perfectly pure
print(round(entropy(np.array([1,1,1,1,1,0])), 3))   # 5 cats/1 dog → ~0.65

    Those middle numbers match the slide exactly. Real libraries usually default to a close cousin, Gini impurity — the chance you'd mislabel a random example if you guessed by the set's class proportions:

    \[G = 1 - p_1^2 - p_0^2.\]
    def gini(y):
    if len(y) == 0:
        return 0.0
    p1 = y.mean()
    return 1 - p1**2 - (1 - p1)**2

print(gini(y))                          # → 0.5, its own peak for a 50/50 mix

    Entropy and Gini have nearly the same shape (both zero when pure, both maximal at 50/50), so they almost always grow the same tree. Gini is a hair cheaper to compute, which is why scikit-learn uses it by default; entropy is one keyword away. Use entropy below so the numbers line up with the lessons.

    2. Scoring a split: information gain¶

    A split sends some examples left and some right, each branch with its own entropy. You don't just average the two — you take a weighted average, weighting each branch by the fraction of examples that land in it (a branch holding more animals matters more). The value of the split is how much that weighted entropy drops below the parent's — the information gain:

    \[\text{gain} = H(\text{parent}) - \Big(w_{\text{left}}H(\text{left}) + w_{\text{right}}H(\text{right})\Big).\]

    For a binary feature, "left" is the rows where the feature is 0 and "right" where it's 1:

    def information_gain(X, y, feature):
    col = X[:, feature]
    left, right = y[col == 0], y[col == 1]
    n = len(y)
    weighted = (len(left) / n) * entropy(left) + (len(right) / n) * entropy(right)
    return entropy(y) - weighted            # drop in impurity

    Now score every feature and see which question is most informative:

    for f, name in enumerate(feature_names):
    print(f"{name:12s} gain = {information_gain(X, y, f):.3f}")
# ear shape    gain = 0.278   ← the winner
# face shape   gain = 0.035
# whiskers     gain = 0.125

    Ear shape wins with gain ≈ 0.28 — exactly the slide's number. Splitting on it gives a left branch (floppy) that's mostly dogs and a right branch (pointy) that's mostly cats: p₁ = 1/5 and 4/5, each weighted 5/10. That's the whole engine.

    Measuring the drop rather than the raw branch entropy also gives you a free stopping rule: if the best available split barely lowers entropy, don't bother — leaving the node as a leaf keeps the tree small and fights overfitting.

    3. From gain to a tree: one greedy split¶

    The full algorithm (scikit-learn calls it CART) is just this: pick the split with the highest gain, then recurse on each branch, stopping when a branch is pure or you hit a depth limit. It's greedy — it grabs the best split now without checking whether a different early split would pay off deeper down — which is fast and usually good enough. Here we do the first split, the one that becomes the root:

    best = max(range(X.shape[1]), key=lambda f: information_gain(X, y, f))
print(f"root question: split on '{feature_names[best]}'")

col = X[:, best]
print("  left  (floppy):", y[col == 0], "→ predict", round(y[col == 0].mean()))
print("  right (pointy):", y[col == 1], "→ predict", round(y[col == 1].mean()))

    Each leaf predicts its majority class (round(mean) of a 0/1 array). Recurse the same information_gain search on the two branches and you've hand-built a decision tree — but you'd never do that in practice, because the library does it faster and prunes for you.

    4. The library way — DecisionTreeClassifier¶

    To watch a tree actually overfit, switch to a 2-D dataset with curved structure and some noise, split into train/test:

    from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split

Xm, ym = make_moons(n_samples=500, noise=0.30, random_state=42)
X_tr, X_te, y_tr, y_te = train_test_split(Xm, ym, test_size=0.25, random_state=42)

    Grow a tree with no depth limit and it will keep splitting until every training leaf is pure:

    from sklearn.tree import DecisionTreeClassifier

tree = DecisionTreeClassifier(random_state=42)      # no max_depth → grows all the way
tree.fit(X_tr, y_tr)
print(f"train {tree.score(X_tr, y_tr):.3f}   test {tree.score(X_te, y_te):.3f}")
# train 1.000   test 0.856  ← memorized the training set, gap = overfitting

    Perfect on training, worse on test: the classic overfitting signature. An unconstrained tree carves the plane into tiny boxes around individual noisy points. The cure is pruning — cap the depth so it can't:

    pruned = DecisionTreeClassifier(max_depth=3, random_state=42)
pruned.fit(X_tr, y_tr)
print(f"train {pruned.score(X_tr, y_tr):.3f}   test {pruned.score(X_te, y_te):.3f}")
# train 0.899   test 0.896  ← lower training score, but the gap closed

    You can read exactly what it learned — tree.feature_importances_, or sklearn.tree.plot_tree(pruned) to draw the boxes. That readability is why trees are called "white-box" models. But one tree is twitchy: change a few training points and the whole structure can flip. The fix is to stop relying on a single tree.

    5. Ensemble #1 — Random Forests (bagging + random features)¶

    The wisdom of the crowd: ask one expert and you get one opinion; ask a thousand so-so predictors and average them, and the errors cancel out. For trees this is a random forest. Two ingredients from the lesson, both easy to write:

    1. Bagging — for each tree, draw a bootstrap sample (sample the training rows with replacement, same size m), so every tree sees a slightly different dataset.
    2. Random features — at each split, consider only a random subset of k ≈ √n features, so the trees don't all latch onto the same dominant split and end up clones.

    Here's the whole algorithm by hand — a loop of shallow-ish trees, then a majority vote:

    from scipy.stats import mode

rng = np.random.default_rng(0)
m = len(X_tr)
trees = []
for b in range(100):                                  # B = 100 trees
    idx = rng.integers(0, m, m)                       # bootstrap: sample rows WITH replacement
    t = DecisionTreeClassifier(max_features="sqrt", random_state=b)   # random √n features/split
    t.fit(X_tr[idx], y_tr[idx])
    trees.append(t)

votes = np.array([t.predict(X_te) for t in trees])    # (100 trees, n_test)
y_pred = mode(votes, axis=0, keepdims=False).mode      # majority vote per example
print(f"hand-rolled forest test {(y_pred == y_te).mean():.3f}")
# hand-rolled forest test 0.904  ← beats the single tree's 0.856

    That's genuinely all a random forest is. scikit-learn wraps it in one estimator (and does the same thing, faster and in parallel):

    from sklearn.ensemble import RandomForestClassifier

forest = RandomForestClassifier(n_estimators=100, max_features="sqrt", random_state=42)
forest.fit(X_tr, y_tr)
print(f"forest test {forest.score(X_te, y_te):.3f}")   # ~0.90, and far more stable than one tree

    More trees never hurt accuracy, but you hit diminishing returns fast — 100–128 is the sweet spot; 1,000 just burns compute for a rounding error. Because bagging already averages over many small perturbations of the data, the forest barely moves when you nudge the training set — that robustness is the payoff.

    6. Ensemble #2 — Boosting / XGBoost¶

    A forest builds its trees independently and averages them. Boosting builds them in sequence, each new tree focusing on the examples the ensemble still gets wrong — like practicing piano by drilling only the bars you keep fumbling, instead of replaying the whole piece. Trees are added one at a time, each correcting its predecessors' residual mistakes. scikit-learn ships this as GradientBoostingClassifier:

    from sklearn.ensemble import GradientBoostingClassifier

gb = GradientBoostingClassifier(n_estimators=100, learning_rate=0.1,
                                max_depth=2, random_state=42)   # small trees, added in sequence
gb.fit(X_tr, y_tr)
print(f"gradient boosting test {gb.score(X_te, y_te):.3f}")     # ~0.90

    Note the trees are shallow (max_depth=2) — boosting wants many weak learners, not a few strong ones, and learning_rate shrinks each tree's contribution so the ensemble improves in small, safe steps.

    XGBoost ("Extreme Gradient Boosting") is the industrial version of this idea and the most common tree implementation in production and on Kaggle: fast, sensible defaults, and built-in regularization to keep it from overfitting. Same three-line API (pip install xgboost first):

    from xgboost import XGBClassifier                   # XGBRegressor for regression targets

xgb = XGBClassifier(n_estimators=100, learning_rate=0.1, max_depth=2)
xgb.fit(X_tr, y_tr)
print(f"xgboost test {xgb.score(X_te, y_te):.3f}")  # competitive with / beats the others

    Under the hood XGBoost weights the misclassified examples rather than literally resampling them, but the "focus on the mistakes" intuition is exactly right. For everyday tabular data, a random forest or XGBoost is very often the strongest thing you can reach for — no feature scaling, handles mixed feature types, and hard to beat.

    7. Your turn¶

    These aren't new exercises — each is a small tweak to the code you already ran above, meant to build intuition by poking at it. Try each yourself first; the solution is one click away if you get stuck. Do at least the first two.

    1. Swap entropy for Gini. Re-rank the three cat features using gini instead of entropy in information_gain. Does ear shape still win? (It should — the two criteria almost always agree.)

    Solution 
    def gain_gini(X, y, feature):
    col = X[:, feature]
    left, right = y[col == 0], y[col == 1]
    n = len(y)
    weighted = (len(left)/n)*gini(left) + (len(right)/n)*gini(right)
    return gini(y) - weighted

for f, name in enumerate(feature_names):
    print(f"{name:12s} {gain_gini(X, y, f):.3f}")
# ear shape still has the largest drop — same winner as entropy

    2. Sweep the tree depth. Loop max_depth from 1 to 10, printing train and test accuracy for each. Watch the train score march to 1.0 while test peaks and then sags — that's the overfitting curve in one table.

    Solution 
    for d in range(1, 11):
    t = DecisionTreeClassifier(max_depth=d, random_state=42).fit(X_tr, y_tr)
    print(f"depth {d:2d}: train {t.score(X_tr, y_tr):.3f}  test {t.score(X_te, y_te):.3f}")
# train keeps rising; test tops out around depth 3-5 then drifts down

    3. One tree vs. a hundred. Set n_estimators=1 in RandomForestClassifier, fit, and compare its test score to the 100-tree forest. Then feel the stability: refit each a few times with different random_states and watch how much more the single tree's score jumps around.

    Solution 
    for n in (1, 5, 100):
    f = RandomForestClassifier(n_estimators=n, random_state=42).fit(X_tr, y_tr)
    print(f"{n:3d} trees: test {f.score(X_te, y_te):.3f}")
# accuracy climbs and then plateaus; the 1-tree score is also far twitchier run to run

    4. Kill the random-feature trick. Set max_features=None in your hand-rolled forest (so every tree considers all features at each split — pure bagging). Compare the vote accuracy. Removing the feature randomness makes the trees more alike, so averaging helps a little less.

    Solution 
    trees = []
for b in range(100):
    idx = rng.integers(0, m, m)
    t = DecisionTreeClassifier(max_features=None, random_state=b).fit(X_tr[idx], y_tr[idx])
    trees.append(t)
votes = np.array([t.predict(X_te) for t in trees])
y_pred = mode(votes, axis=0, keepdims=False).mode
print(f"bagging-only test {(y_pred == y_te).mean():.3f}")   # usually a touch below the √n forest

    5. Turn the boosting knobs. Try learning_rate in (0.01, 0.1, 1.0) on GradientBoostingClassifier. A tiny rate under-fits in 100 trees; a large one overshoots. This is the same learning-rate trade-off you met in gradient descent.

    Solution 
    for lr in (0.01, 0.1, 1.0):
    g = GradientBoostingClassifier(n_estimators=100, learning_rate=lr,
                                   max_depth=2, random_state=42).fit(X_tr, y_tr)
    print(f"lr={lr}: train {g.score(X_tr, y_tr):.3f}  test {g.score(X_te, y_te):.3f}")
# 0.01 underfits (both low); 0.1 is the sweet spot; 1.0 overfits (train↑, test↓)
