    C1 · W3 — Logistic Regression, Decision Boundaries & Regularization, in Code¶

    Recommended before this lab

    You'll get the most out of this once you've watched the Course 1 · Week 3 lessons the code builds on — the model, the boundary, the cost, and how regularization tames it:

    • Logistic Regression
    • Decision Boundary
    • Cost Function for Logistic Regression
    • Cost Function with Regularization → Regularized Logistic Regression

    Not strict prerequisites — do the lab in whatever order you like — but this is the theory it turns into code.

    In Week 1 you fit a straight line to predict a number. Now the target is a label — spam / not-spam, malignant / benign, pass / fail. The trick is small and reuses almost everything you already have: take the same linear score w·x + b, squash it through an S-shaped sigmoid so it lands between 0 and 1, and read that as a probability. The same gradient-descent engine trains it; the only genuinely new pieces are the squashing function, the log loss that replaces squared error, and a regularization knob that stops a flexible model from memorizing its training data.

    We'll build it from the inside out:

    1. From scratch in NumPy — sigmoid → probability → log-loss cost → gradient descent, and the decision boundary you can actually plot.
    2. Bend the boundary — polynomial features let logistic regression draw curves, which also lets it overfit — so we add the λ penalty and watch the boundary calm down.
    3. The library way — scikit-learn's LogisticRegression in three lines, where regularization is always on and controlled by C.

    0. Setup and some data¶

    Two features, two classes. We draw two Gaussian blobs — one per class — so a straight line can separate most of them. Each row of X is one example; y is its label (0 or 1).

    import numpy as np

rng = np.random.default_rng(42)          # fixed seed → reproducible "random" data
m = 200                                   # number of training examples

X0 = rng.normal(loc=[-1.0, -1.0], scale=1.0, size=(m // 2, 2))   # the y=0 cloud
X1 = rng.normal(loc=[ 1.5,  1.5], scale=1.0, size=(m // 2, 2))   # the y=1 cloud
X  = np.vstack([X0, X1])                                          # (200, 2)
y  = np.r_[np.zeros(m // 2), np.ones(m // 2)].reshape(-1, 1)      # (200, 1): 100 zeros then 100 ones

    In the lesson's notation there are m = 200 examples, each a pair (x⁽ⁱ⁾, y⁽ⁱ⁾) where y⁽ⁱ⁾ ∈ {0, 1}.

    1. The sigmoid, from scratch¶

    The one new building block. The sigmoid (a.k.a. logistic) function maps any real number z into the open interval (0, 1):

    \[g(z) = \frac{1}{1 + e^{-z}}\]

    Written with NumPy it's one line, and because np.exp is element-wise it works on a single number or a whole array at once:

    def sigmoid(z):
    return 1 / (1 + np.exp(-z))

print(sigmoid(np.array([-6, 0, 6])))   # → [0.0025, 0.5, 0.9975]

    Read off the three anchor points that give it the S-shape: a large negative z maps near 0, z = 0 maps exactly to 0.5, and a large positive z maps near 1. That's the whole reason we use it — it turns an unbounded score into something we can read as a probability.

    2. The model: linear score → sigmoid → probability¶

    Logistic regression is just linear regression's z = w·x + b with a sigmoid bolted on the end:

    \[f_{\vec{w},b}(\vec{x}) = g(\vec{w}\cdot\vec{x} + b) = \frac{1}{1 + e^{-(\vec{w}\cdot\vec{x}+b)}}\]

    We reuse the Week-1 trick — prepend a column of 1s so the bias b becomes "the weight on a feature that's always 1." Then the whole dataset's scores are one matrix multiply, and one sigmoid turns them into probabilities:

    X_b = np.c_[np.ones((m, 1)), X]          # prepend x0 = 1 → shape (200, 3)

def predict_proba(X_b, theta):
    return sigmoid(X_b @ theta)          # ŷ = g(X · θ),  θ = [b, w1, w2]

    theta holds all three parameters: theta[0] is the bias b, theta[1:] are the two weights. The output is the model's estimated probability that y = 1 — a tumor scoring 0.7 means "70% chance malignant."

    The score z = w·x + b is sometimes called the logit or log-odds — it's the log of the ratio between the two class probabilities. You don't need that for the course, but it's why scikit-learn calls this LogisticRegression.

    3. The cost: log loss, from scratch¶

    Squared error was perfect for linear regression, but feeding the sigmoid into it produces a wiggly, non-convex surface full of local minima gradient descent can get stuck in. So logistic regression uses a different per-example loss — one that's near 0 for a confident correct prediction and shoots toward ∞ for a confident wrong one:

    \[L\big(f, y\big) = \begin{cases} -\log(f) & \text{if } y = 1,\\ -\log(1 - f) & \text{if } y = 0. \end{cases}\]

    Because y is only ever 0 or 1, both cases collapse into one line (one term always zeroes out), and the cost is the average over all m examples:

    \[J(\vec{w}, b) = -\frac{1}{m}\sum_{i=1}^{m}\Big[y^{(i)}\log\big(f^{(i)}\big) + \big(1 - y^{(i)}\big)\log\big(1 - f^{(i)}\big)\Big]\]
    def log_loss(X_b, y, theta):
    p = predict_proba(X_b, theta)
    eps = 1e-9                                    # guard against log(0) when p hits 0 or 1
    return float(-np.mean(y * np.log(p + eps) + (1 - y) * np.log(1 - p + eps)))

    This isn't arbitrary — it falls out of maximum likelihood estimation (asking which parameters make the observed labels most probable), and crucially it's convex again, so gradient descent reliably finds the one global minimum.

    4. Train it: gradient descent, from scratch¶

    Here's the payoff for all the Week-1 work: the gradient of the log loss has the exact same shape as linear regression's — prediction minus truth, times the feature, averaged:

    \[\frac{\partial J}{\partial \theta_j} = \frac{1}{m}\sum_{i=1}^{m}\big(f^{(i)} - y^{(i)}\big)\,x_j^{(i)}\]

    The only difference from Week 1 is that f is now the sigmoid, not the raw linear score. So the training loop is nearly identical to the linear-regression one:

    eta = 0.1                                  # learning rate
n_epochs = 5000
theta = np.zeros((3, 1))                    # start from all-zeros (a flat 0.5-everywhere model)

for epoch in range(n_epochs):
    p = sigmoid(X_b @ theta)               # current probabilities
    gradients = X_b.T @ (p - y) / m        # same (ŷ − y)·x form as linear regression
    theta = theta - eta * gradients        # step downhill

print("theta:", theta.ravel())
print("cost :", round(log_loss(X_b, y, theta), 4))

    There's no normal equation for logistic regression — no one-line closed-form shortcut like Week 1's — so iterating downhill isn't just a way to train it, it's the only way. Good thing the engine already works.

    We can check accuracy by thresholding the probabilities at 0.5:

    preds = (predict_proba(X_b, theta) >= 0.5).astype(int)
print("accuracy:", float((preds == y).mean()))   # ~0.98 on these two blobs

    5. The decision boundary, plotted¶

    The decision boundary is where the model flips its 0-vs-1 call. Chase the 0.5 threshold back through the math: f ≥ 0.5 exactly when the sigmoid's input z ≥ 0, i.e. when

    \[\vec{w}\cdot\vec{x} + b \ge 0.\]

    So the boundary is the line w·x + b = 0. With two features, θ₀ + θ₁x₁ + θ₂x₂ = 0 rearranges to a straight line we can draw:

    import matplotlib.pyplot as plt

plt.scatter(X[:, 0], X[:, 1], c=y.ravel(), cmap="bwr", edgecolor="k")

xs = np.array([X[:, 0].min(), X[:, 0].max()])
ys = -(theta[0, 0] + theta[1, 0] * xs) / theta[2, 0]    # solve θ₀+θ₁x₁+θ₂x₂=0 for x₂
plt.plot(xs, ys, "k--", label="decision boundary")

plt.xlabel("x1"); plt.ylabel("x2"); plt.legend(); plt.show()

    Points on one side of the dashed line predict 1, the other side predict 0 — and with only raw features the boundary is always a straight line. To bend it, we need more features.

    6. Bending the boundary — and overfitting¶

    Some data can't be split by a straight line — imagine one class forming a ring around the other. Just like linear regression, we can feed polynomial features (x₁², x₁x₂, x₂², …) into logistic regression, and the boundary in the original 2-D space becomes a curve (a circle, ellipse, or something wigglier).

    Let's make a ring-shaped dataset and a helper that expands two features into all monomials up to a given degree:

    from sklearn.datasets import make_circles

Xc, yc = make_circles(n_samples=200, noise=0.12, factor=0.4, random_state=42)
yc = yc.reshape(-1, 1)

def map_features(X2, degree):
    """(m, 2) → all monomials x1^a · x2^b with 1 ≤ a+b ≤ degree (no bias column)."""
    x1, x2 = X2[:, 0], X2[:, 1]
    feats = [x1**(i - j) * x2**j for i in range(1, degree + 1) for j in range(i + 1)]
    return np.column_stack(feats)

    Now reuse the same gradient-descent loop, just on the mapped features. A degree-6 map gives the model plenty of freedom — enough to trace a very contorted boundary:

    def train(Xmap, y, lam=0.0, eta=0.2, n_epochs=20000):
    Xb = np.c_[np.ones((len(Xmap), 1)), Xmap]     # add bias column
    theta = np.zeros((Xb.shape[1], 1))
    for _ in range(n_epochs):
        p = sigmoid(Xb @ theta)
        grad = Xb.T @ (p - y) / len(y)
        reg = (lam / len(y)) * theta               # the λ penalty (added in the next section)
        reg[0] = 0                                 # never regularize the bias
        theta = theta - eta * (grad + reg)
    return theta

degree = 6
theta_overfit = train(map_features(Xc, degree), yc, lam=0.0)   # lam=0 → NO regularization

    To see the boundary now that it's a curve, we evaluate the model on a fine grid and let contourf shade the two regions — this is the "decision regions" plot from Raschka, adapted:

    def plot_boundary(theta, degree, X2, y):
    x1s = np.linspace(X2[:, 0].min() - 0.5, X2[:, 0].max() + 0.5, 300)
    x2s = np.linspace(X2[:, 1].min() - 0.5, X2[:, 1].max() + 0.5, 300)
    xx1, xx2 = np.meshgrid(x1s, x2s)
    grid = np.c_[xx1.ravel(), xx2.ravel()]
    G = np.c_[np.ones((len(grid), 1)), map_features(grid, degree)]
    probs = sigmoid(G @ theta).reshape(xx1.shape)
    plt.contourf(xx1, xx2, probs, levels=[0, 0.5, 1], alpha=0.3, cmap="bwr")
    plt.scatter(X2[:, 0], X2[:, 1], c=y.ravel(), cmap="bwr", edgecolor="k")
    plt.show()

plot_boundary(theta_overfit, degree, Xc, yc)

    With no penalty and 27 polynomial features, the boundary bends itself into knots to chase every noisy point — a textbook overfit. It nails the training data but would generalize badly. Time for the knob that fixes it.

    7. Regularization, from scratch¶

    The cure is to penalize large weights so the model can't contort so freely. Add a term that grows with the size of the weights to the cost:

    \[J(\vec{w},b) = \underbrace{-\frac{1}{m}\sum_i\big[\dots\big]}_{\text{fit the data}} \;+\; \frac{\lambda}{2m}\sum_{j=1}^{n} w_j^2.\]

    The two terms pull against each other: the first wants to fit every point, the second wants small (simple) weights. λ sets the trade-off, and by convention the bias b is not penalized. In the gradient this adds exactly one term, (λ/m)·wⱼ, to each weight's slope — which is the reg line already in our train function above. So regularizing is just passing a non-zero lam:

    theta_reg = train(map_features(Xc, degree), yc, lam=1.0)   # same model, now with λ = 1
plot_boundary(theta_reg, degree, Xc, yc)

    Same 27 features, same loop — but the boundary is now a smooth near-circle instead of a tangle. That's regularization doing its job: keeping every feature available while stopping any one weight from dominating. Watch the extremes:

    • λ = 0 → no penalty → the wiggly overfit from §6.
    • λ enormous → all weights driven toward 0 → the model collapses toward a flat constant → underfit.
    • λ just right → keeps the features, fits a sensible smooth boundary.
    for lam in (0.0, 1.0, 1000.0):
    th = train(map_features(Xc, degree), yc, lam=lam)
    p = sigmoid(np.c_[np.ones((len(Xc), 1)), map_features(Xc, degree)] @ th)
    acc = float(((p >= 0.5).astype(int) == yc).mean())
    print(f"lambda={lam:>7}:  train accuracy={acc:.3f},  ||w||={np.linalg.norm(th[1:]):.2f}")

    Notice how ||w|| (the total weight size) shrinks as λ grows — that's literally what the penalty rewards.

    8. The library way — scikit-learn¶

    In real work you don't hand-roll any of this. scikit-learn's LogisticRegression fits the model with a fast, robust convex optimizer (lbfgs by default) and keeps the bias (intercept_) separate from the weights (coef_), so you pass raw X — no bias column:

    from sklearn.linear_model import LogisticRegression

clf = LogisticRegression()
clf.fit(X, y.ravel())                          # sklearn wants a 1-D y

print("bias   :", clf.intercept_)              # ≈ our theta[0]
print("weights:", clf.coef_)                   # ≈ our theta[1:]
print("probs  :", clf.predict_proba(X[:3]))    # P(y=0), P(y=1) per row — they sum to 1
print("labels :", clf.predict(X[:3]))          # the 0/1 call at the 0.5 threshold

    One gotcha worth memorizing: scikit-learn's regularization dial is C, not λ, and it's the inverse — C = 1/λ. So a small C means strong regularization (heavy penalty, simpler model) and a large C means weak regularization. And unlike our from-scratch model, sklearn's LogisticRegression regularizes by default (L2). You can watch C do the same thing our λ did — on the ring data, via a polynomial pipeline:

    from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures

for C in (0.001, 1.0, 1000.0):                 # small C = strong reg = simpler boundary
    model = make_pipeline(PolynomialFeatures(6), LogisticRegression(C=C, max_iter=10000))
    model.fit(Xc, yc.ravel())
    print(f"C={C:>7}:  train accuracy={model.score(Xc, yc.ravel()):.3f}")

    For more than two classes, LogisticRegression generalizes on its own via softmax regression (a.k.a. multinomial logistic regression): instead of one probability it outputs one per class, all summing to 1, and predicts the biggest. Same idea, more outputs — no extra code from you.

    9. Your turn¶

    These aren't new exercises — each is a small tweak to the code you already ran above, meant to build intuition by poking at it. Try each yourself first; the solution is one click away if you get stuck. Do at least the first two.

    1. Move the threshold. In §5 we predicted 1 when the probability ≥ 0.5. Raise the bar to 0.8 (only confident positives count) and count how many fewer 1s you predict.

    Solution 
    p = predict_proba(X_b, theta)
print("threshold 0.5:", int((p >= 0.5).sum()), "positives")
print("threshold 0.8:", int((p >= 0.8).sum()), "positives")   # fewer — the bar is higher

    2. Watch a confident-but-wrong prediction blow up the loss. Feed log_loss a point the model is sure about and wrong about, and compare its loss to a correct one.

    Solution 
    # a y=1 example the model calls 0.99 (right) vs 0.01 (confidently wrong)
Xone = np.array([[1.0, 2.0, 2.0]])            # bias col + a point deep in the y=1 blob
right = log_loss(Xone, np.array([[1.0]]), theta)
wrong = log_loss(Xone, np.array([[0.0]]), theta)   # same point, label flipped to 0
print("loss when right:", round(right, 3))
print("loss when wrong:", round(wrong, 3))    # far larger — confident-wrong is punished hard

    3. Turn regularization off and see the overfit. Re-run §7's boundary with lam=0.0 next to lam=1.0 and eyeball how much wigglier the unregularized curve is.

    Solution 
    plot_boundary(train(map_features(Xc, degree), yc, lam=0.0), degree, Xc, yc)   # tangled
plot_boundary(train(map_features(Xc, degree), yc, lam=1.0), degree, Xc, yc)   # smooth

    4. Crank λ to the underfit extreme. Train with lam=1e5 and check the weights nearly vanish, leaving an almost-flat model.

    Solution 
    th = train(map_features(Xc, degree), yc, lam=1000.0)
print("||w|| =", round(float(np.linalg.norm(th[1:])), 4))   # ≈ 0: weights crushed
plot_boundary(th, degree, Xc, yc)                            # boundary barely bends

    5. Confirm from-scratch ≈ scikit-learn. On the linear blob data, print your §4 theta next to sklearn's [intercept_, coef_]. (They won't be identical — sklearn regularizes by default and uses a different optimizer — but the sign and rough size should match.)

    Solution 
    print("scratch :", theta.ravel())
print("sklearn :", np.r_[clf.intercept_, clf.coef_.ravel()])
# weaken sklearn's regularization (big C) to line them up more closely:
strong = LogisticRegression(C=1e6).fit(X, y.ravel())
print("sklearn (C=1e6):", np.r_[strong.intercept_, strong.coef_.ravel()])
