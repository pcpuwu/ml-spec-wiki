    C3 · W2 — PCA & Collaborative-Filtering Recommenders, in Code¶

    Recommended before this lab

    This week bundles two unsupervised ideas — PCA (squash many features into 2–3) and collaborative filtering (learn recommendations from a table full of holes). Watch these first and the code below is just the math written out:

    • Reducing the Number of Features → PCA Algorithm → PCA in Code
    • Collaborative Filtering Algorithm

    Not strict prerequisites — do the lab in any order — but this is the theory it turns into code.

    This lab has two independent halves, matching the two topics of the week:

    • Part I — PCA. Find the axis your data actually varies along, then throw the rest away. We build it two ways from scratch (covariance + eigenvectors, and the SVD) so you see they land on the same axes, then do it in one line with scikit-learn.
    • Part II — Collaborative filtering. Given a ratings table where most cells are blank, learn a latent-factor vector for every user and every item at once, purely by gradient descent — then read off predictions for the blanks.

    A note on the recommender. PCA is textbook material (Géron Ch. 8, Raschka Ch. 5). Matrix-factorization recommenders are not — neither book covers them. So Part II is built from first principles straight out of Ng's lecture: define the cost, take its gradient, roll downhill. It's the same "measure a cost, follow the slope" engine from the very first lab.

    Part I — PCA¶

    0. Setup and some data¶

    We'll make a 2-D cloud that's really 1-D in disguise: both features track one hidden "size" variable, plus a little noise. PCA should discover that hidden axis.

    import numpy as np

rng = np.random.default_rng(42)
m = 200
t = rng.standard_normal(m)                    # the hidden 1-D signal
X = np.c_[3 * t + 0.5 * rng.standard_normal(m),   # feature 1 tracks t strongly
          2 * t + 0.5 * rng.standard_normal(m)]   # feature 2 tracks t too

    X is (200, 2). Plot it and you'd see a fat diagonal streak — the two features are correlated, so almost all the spread lies along one diagonal direction. PCA's whole job is to find that direction.

    1. Step zero: center the data¶

    PCA is about variance (spread), and variance is measured around the mean. So every route starts by subtracting each feature's mean — exactly the "normalize features to zero mean" preprocessing step from the lecture. (If your features were on wildly different scales — GDP in trillions vs. a count under 100 — you'd also divide by the standard deviation first. Ours are comparable, so centering is enough.)

    X_c = X - X.mean(axis=0)                       # zero-centered; PCA assumes this

    2. Route A — covariance matrix + eigenvectors (Raschka's from-scratch recipe)¶

    Here's the classic derivation. "Which direction has the most spread?" is answered by the covariance matrix — a small n×n table (here 2×2) whose entries measure how each pair of features varies together. Its eigenvectors are the principal-component axes, and each eigenvector's eigenvalue is the variance along that axis. Bigger eigenvalue → more important axis.

    cov = np.cov(X_c.T)                            # 2×2 covariance matrix
eig_vals, eig_vecs = np.linalg.eigh(cov)       # eigh: for symmetric matrices, real answers

# eigh returns them smallest-first — flip to biggest-first so PC1 comes first
order = np.argsort(eig_vals)[::-1]
eig_vals, eig_vecs = eig_vals[order], eig_vecs[:, order]

print("variance per axis:", eig_vals)          # first number >> second
print("PC1 direction:", eig_vecs[:, 0])        # the unit vector u from the lecture

    Use np.linalg.eigh (not eig): a covariance matrix is symmetric, and eigh is the numerically stable version that always returns real eigenvalues. The columns of eig_vecs are the unit-length axes — the same u = [0.71, 0.71]-style vector the lesson projected onto.

    The principal component is eig_vecs[:, 0]: the axis with the largest eigenvalue, i.e. the direction the data is most spread out along. The second column is automatically at 90° to it — eigenvectors of a symmetric matrix are orthogonal, which is why PCA's axes always come out perpendicular.

    3. Route B — the SVD (Géron's route, and what scikit-learn actually does)¶

    Building the covariance matrix and eigen-decomposing it is one valid recipe, but it's not how production code does it. There's a single matrix factorization — the singular value decomposition — that hands you the principal components directly from the centered data, skipping the covariance matrix entirely and with better numerical behavior:

    \[X_c = U\,\Sigma\,V^\top\]

    The rows of Vᵀ are the principal components, already sorted best-first.

    U, s, Vt = np.linalg.svd(X_c, full_matrices=False)

print("PC1 direction:", Vt[0])                 # same axis Route A found (maybe sign-flipped)

    Both routes describe the same line. The only thing that can differ is a sign flip — the axis [0.83, 0.55] and [-0.83, -0.55] are the same line pointing opposite ways, and which one you get depends on the library version. That's expected and harmless (just retrain any downstream model whenever you refit PCA).

    The singular values s even carry the variances: s**2 is proportional to the eigenvalues from Route A.

    4. Projecting down (and reconstructing back)¶

    To actually reduce 2-D → 1-D, project every centered point onto the top axis — which, from the lesson, is just a dot product with the unit vector. Stack the top k axes into a matrix W and it's one matrix multiply for the whole dataset:

    \[Z = X_c\,W\]
    W = Vt[:1].T                                   # keep the top 1 component → shape (2, 1)
Z = X_c @ W                                     # every point becomes ONE number
print(Z[:3].ravel())                            # e.g. [-1.31, 2.99, -3.09]

    Each 2-number example is now a single number — its position along the principal axis. To go the other way (reconstruction), multiply back and add the mean you subtracted:

    X_recon = Z @ W.T + X.mean(axis=0)             # approximate the original 2-D points
print("reconstruction MSE:", np.mean((X - X_recon) ** 2))   # tiny — we lost almost nothing

    You can't recover the originals exactly (the second dimension was thrown away), but because that dimension held almost no variance, the reconstruction is nearly perfect — which is the whole promise of PCA.

    5. How much did we keep? Explained variance ratio¶

    The honest question after any dimensionality cut is "what fraction of the information survived?" That's the explained variance ratio: each axis's variance divided by the total. From the SVD's singular values:

    ratio = s**2 / (s**2).sum()
print(ratio)                                    # ≈ [0.976, 0.024]

    The first axis alone explains ~98% of the spread — so collapsing this data to one number loses ~2%. On real data you'd take the cumulative sum and keep enough axes to reach, say, 95%: d = np.argmax(np.cumsum(ratio) >= 0.95) + 1.

    6. The library way — scikit-learn¶

    Nobody hand-rolls the above at work. scikit-learn does all of Parts 1–5 — centering, SVD, projection, variance accounting — behind three lines:

    from sklearn.decomposition import PCA

pca = PCA(n_components=1)
Z_sk = pca.fit_transform(X)                     # note: pass the RAW X — fit centers it for you
print(pca.explained_variance_ratio_)            # ≈ [0.976]
print(Z_sk[:3].ravel())                         # same numbers as our Z (up to a sign flip)

    Two conveniences to notice: fit_transform centers the data for you (so you feed raw X, not X_c), and pca.components_ holds Wᵀ — one row per principal component. You can also pass a float, PCA(n_components=0.95), to say "keep however many axes I need for 95% of the variance" and let it pick the number.

    What is PCA good for today? Ng's honest take: mainly visualization — squash 50 features to 2–3 and scatter-plot them to eyeball structure. The old uses (compressing data, speeding up training) matter far less now that storage is cheap and deep nets happily eat high-dimensional input directly.

    Part II — Collaborative-Filtering Recommenders¶

    7. The setup: a ratings table full of holes¶

    A recommender's raw material is a big ratings matrix Y: rows are movies, columns are users, and cell Y[i, j] is how many stars user j gave movie i. The catch — most cells are empty, because no one has seen most movies. We track which cells are filled with a mask R (R[i, j] = 1 if rated). The goal: predict the blanks.

    Instead of a real dataset, we'll fabricate a low-rank one so we can check our answers. We invent secret feature vectors for every movie and every user, multiply them to get the "true" complete table, then hide 60% of the cells and see if the algorithm can rediscover them.

    import numpy as np

rng = np.random.default_rng(0)
n_movies, n_users, k_true = 20, 15, 3
true_X = rng.standard_normal((n_movies, k_true))   # secret movie features
true_W = rng.standard_normal((n_users,  k_true))   # secret user tastes
true_b = rng.standard_normal(n_users)              # secret per-user bias

full = true_X @ true_W.T + true_b                  # the complete "true" ratings
R = (rng.random((n_movies, n_users)) < 0.4).astype(float)   # observe only ~40%
Y = full * R                                       # the table we're actually handed
print("observed", int(R.sum()), "of", R.size, "cells")   # ~120 of 300

    (Real ratings are integers 1–5; ours are continuous for simplicity — the algorithm is identical.)

    8. The model and the cost, from scratch¶

    From Using Per-Item Features, the predicted rating of movie i by user j is a dot product of a movie-feature vector x⁽ⁱ⁾ and a user-parameter vector w⁽ʲ⁾, plus a per-user bias:

    \[\hat{y}(i,j) = \vec{w}^{(j)}\cdot\vec{x}^{(i)} + b^{(j)}\]

    The twist of collaborative filtering: we know neither the x's nor the w's. We learn both at the same time. As one matrix multiply, all predictions at once are X @ W.T + b:

    def predict(X, W, b):
    return X @ W.T + b            # (n_movies, k) @ (k, n_users) → (n_movies, n_users)

    The cost is the squared error over the observed cells only — the mask R zeros out the blanks so they never contribute — plus L2 regularization on both factor tables:

    def cost(X, W, b, Y, R, lam):
    err = (predict(X, W, b) - Y) * R           # error, but ONLY where we have a rating
    reg = 0.5 * lam * ((X**2).sum() + (W**2).sum())
    return 0.5 * (err**2).sum() + reg

    That * R is the entire trick for handling missing data: an unrated cell contributes exactly zero to the loss, so gradient descent simply ignores it.

    9. Gradient descent, from scratch¶

    Same engine as every other lab: take the slope of the cost with respect to every parameter table, and step downhill. Differentiating the masked squared error gives clean matrix gradients (with E = (predict − Y) · R the masked error):

    • dX = E @ W + λX
    • dW = Eᵀ @ X + λW
    • db = E.sum(axis=0) (no regularization on the bias)
    n = 3                                           # how many latent features to learn
X = rng.standard_normal((n_movies, n)) * 0.1    # start small & random
W = rng.standard_normal((n_users,  n)) * 0.1
b = np.zeros(n_users)
eta, lam = 0.01, 0.1

for epoch in range(3000):
    E  = (predict(X, W, b) - Y) * R             # masked error, shared by all gradients
    dX = E @ W       + lam * X
    dW = E.T @ X     + lam * W
    db = E.sum(axis=0)
    X -= eta * dX                               # simultaneous update of all three
    W -= eta * dW
    b -= eta * db
    if epoch % 1000 == 0:
        print(epoch, "cost", round(cost(X, W, b, Y, R, lam), 3))

    All three tables update together from the same error E — the "collaborative" part: every user's ratings help pin down each movie's features, which in turn sharpen every user's predictions.

    Now the payoff — check it against the cells we hid:

    P = predict(X, W, b)
train_rmse = np.sqrt(np.mean((P - full)[R == 1] ** 2))   # cells it trained on
held_rmse  = np.sqrt(np.mean((P - full)[R == 0] ** 2))   # cells it NEVER saw
print("train RMSE", round(train_rmse, 3), " held-out RMSE", round(held_rmse, 3))

    You'll see something like train RMSE 0.08 held-out RMSE 1.22. The held-out error is higher (it's genuinely predicting unseen ratings) but it crushes the naive baseline of "guess each movie's average" (~1.90) — from ~120 known cells it reconstructed the 180 unknown ones. That is a recommender. To recommend for user j, sort column P[:, j] and take the movies they haven't seen with the highest predicted rating.

    New users get sensible defaults for free-ish. The lecture's mean-normalization trick — subtract each movie's average before training, add it back to predict — makes a brand-new user default to the crowd average instead of a useless all-zeros. Try it as a tweak below.

    10. The autodiff way — PyTorch¶

    We hand-derived those three gradients. In practice you let automatic differentiation do it: write only the forward cost, call .backward(), and the framework fills in dX, dW, db for you — which is exactly how you'd scale this to millions of users.

    Ng's lectures implement this in TensorFlow (tf.GradientTape). We use PyTorch here — it's the industry-standard framework and the idea is identical: define the loss, autodiff gives the gradients, an optimizer steps.

    import torch

Yt = torch.tensor(Y, dtype=torch.float32)
Rt = torch.tensor(R, dtype=torch.float32)

# leaf tensors we want gradients for
Xt = (0.1 * torch.randn(n_movies, n)).requires_grad_(True)
Wt = (0.1 * torch.randn(n_users,  n)).requires_grad_(True)
bt = torch.zeros(n_users, requires_grad=True)

opt = torch.optim.Adam([Xt, Wt, bt], lr=0.1)
for epoch in range(2000):
    err  = (Xt @ Wt.T + bt - Yt) * Rt          # the SAME masked error as before
    loss = 0.5 * (err**2).sum() + 0.5 * lam * ((Xt**2).sum() + (Wt**2).sum())
    opt.zero_grad()
    loss.backward()                             # autodiff computes every gradient for us
    opt.step()

print("final loss", round(loss.item(), 3))      # matches the from-scratch run

    Notice the forward line (Xt @ Wt.T + bt - Yt) * Rt is character-for-character the same as our NumPy E — we just stopped writing the gradients by hand. Swapping in the Adam optimizer (instead of plain fixed-step descent) is why we can use a bigger learning rate and fewer epochs.

    11. Your turn¶

    Each is a small tweak to code you already ran — poke at it to build intuition. Try it first; the solution is one click away. Do at least the first two.

    1. Reduce to 2 dimensions instead of 1. Change the PCA projection to keep the top two components and confirm the explained-variance ratio now sums to 1.0 (2-D data → 2 axes → nothing lost).

    Solution 
    W2 = Vt[:2].T                 # keep both components
Z2 = X_c @ W2                 # shape (200, 2) — no reduction, exact
print((s**2 / (s**2).sum())[:2].sum())   # → 1.0
X_recon2 = Z2 @ W2.T + X.mean(axis=0)
print(np.mean((X - X_recon2)**2))        # ≈ 0: reconstruction is exact

    2. Confirm the two PCA routes agree. Print the PC1 axis from the covariance/eigen route and from the SVD route side by side — same direction (possibly sign-flipped)?

    Solution 
    print("eigen PC1:", eig_vecs[:, 0])
print("svd   PC1:", Vt[0])
# same line; if signs are opposite that's the harmless sign ambiguity
print("aligned:", np.allclose(np.abs(eig_vecs[:, 0]), np.abs(Vt[0])))

    3. Starve the recommender of data. Drop the observed fraction from 0.4 to 0.15 (regenerate R and Y), retrain, and watch the held-out RMSE climb — fewer known cells, harder to fill the blanks.

    Solution 
    R = (rng.random((n_movies, n_users)) < 0.15).astype(float)
Y = full * R
X = rng.standard_normal((n_movies, n)) * 0.1
W = rng.standard_normal((n_users,  n)) * 0.1
b = np.zeros(n_users)
for _ in range(3000):
    E = (predict(X, W, b) - Y) * R
    X -= eta * (E @ W + lam * X)
    W -= eta * (E.T @ X + lam * W)
    b -= eta * E.sum(axis=0)
P = predict(X, W, b)
print("held-out RMSE:", np.sqrt(np.mean((P - full)[R == 0]**2)))  # worse than before

    4. Add mean normalization. Subtract each movie's observed-rating mean before training and add it back when predicting — the lecture's fix so a no-ratings user defaults to the crowd average, not zero.

    Solution 
    counts = R.sum(axis=1)
mu = np.where(counts > 0, Y.sum(axis=1) / np.maximum(counts, 1), 0)   # per-movie mean
Yn = (Y - mu[:, None]) * R           # center the observed ratings
# ...train X, W, b on Yn exactly as before...
pred = predict(X, W, b) + mu[:, None]   # add the mean back to predict
# a brand-new (all-zero) user now predicts mu — each movie's average — not 0

    5. Overfit with too many latent features. Bump n from 3 to 12 (the true rank is only 3) and compare train vs. held-out RMSE — the gap widens as the extra factors memorize noise.

    Solution 
    n = 12
X = rng.standard_normal((n_movies, n)) * 0.1
W = rng.standard_normal((n_users,  n)) * 0.1
b = np.zeros(n_users)
for _ in range(3000):
    E = (predict(X, W, b) - Y) * R
    X -= eta * (E @ W + lam * X)
    W -= eta * (E.T @ X + lam * W)
    b -= eta * E.sum(axis=0)
P = predict(X, W, b)
print("train", round(np.sqrt(np.mean((P-full)[R==1]**2)), 3),
      "held", round(np.sqrt(np.mean((P-full)[R==0]**2)), 3))   # bigger gap → turn up lam
